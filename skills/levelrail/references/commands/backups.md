## levelrail-cli backups

Subcommands: clone-restores, copies, coverage, delete, destinations, download, drill, encryption, health, list, list-all, orphans, protect-all, protection, restore, restore-as-new, restores, schedule, targets, trigger, verifications, verify, volumes

```
Usage:
  levelrail-cli backups list <database> [flags]                                    list backup history for a database
  levelrail-cli backups health [flags]                                             every resource with last backup and last verified restore
  levelrail-cli backups protection [--refresh] [flags]                             bucket object lock and versioning status
  levelrail-cli backups coverage [--unprotected] [flags]                           which databases and volumes are protected, verified or not backed up
  levelrail-cli backups protect-all --target ID [--apply] [flags]                  schedule a backup for everything that has none (plan unless --apply)
  levelrail-cli backups orphans list|reclaim <volume> [flags]                      data kept after its database or app was deleted
  levelrail-cli backups drill run|list|show [flags]                                prove a restore works (scratch restore, validate, destroy)
  levelrail-cli backups volumes list|policy|restore <app> <volume> [flags]         app volume backups, retention and hooks, restore to a new volume or node
  levelrail-cli backups list-all [flags]                                           list backup history across every database and app volume
  levelrail-cli backups trigger <database> --target ID [flags]                 trigger a manual backup
  levelrail-cli backups delete <database> <backup-id> [flags]                  delete one archived backup on demand (destructive)
  levelrail-cli backups download <database> <backup-id> [flags]                stream a succeeded backup's own object to stdout
  levelrail-cli backups restore <database> --backup ID --confirm NAME [flags]   restore a database from a backup (destructive)
  levelrail-cli backups restore-as-new <database> --backup ID --new-name NAME [flags] restore a backup into a brand-new database (non-destructive)
  levelrail-cli backups restores <database> [flags]                                list restore attempt history for a database
  levelrail-cli backups clone-restores <database> [flags]                          list restore-as-new attempt history for a database
  levelrail-cli backups schedule set<database> --target ID --cron EXPR [flags] configure a recurring backup
  levelrail-cli backups schedule clear <database> [flags]                       remove a recurring backup
  levelrail-cli backups encryption get|set <destination> [on|off] [flags]       show or change database dump encryption for a destination
  levelrail-cli backups destinations copy show|set <destination|off> [flags]   show or change the second destination backups are copied to
  levelrail-cli backups copies list [--limit N] [flags]                         list each backup's copy status and lag
  levelrail-cli backups verify <database> --backup ID [flags]                   verify a backup is intact (no live restore)
  levelrail-cli backups verifications <database> --backup ID [flags]            list past verification attempts for a backup

Run "levelrail-cli backups <subcommand> -h" for a subcommand's own flags.
```

## levelrail-cli backups destinations

Subcommands: copy

```
Usage:
  levelrail-cli backups destinations copy show [flags]
  levelrail-cli backups destinations copy set <destination> [flags]
  levelrail-cli backups destinations copy set off [flags]

Shows or changes the second destination every new backup is copied to once it
lands in its primary destination. Only backups finished after copying is turned
on are copied. Changing the setting needs a write-sensitive token.

## levelrail-cli backups drill

Subcommands: list, run, show

```
Usage:
  levelrail-cli backups drill run --backup ID [--wait] [flags]   restore a backup into a scratch resource, validate it, destroy it
  levelrail-cli backups drill list [--app A --volume V | --database D] [--limit N]   drill history
  levelrail-cli backups drill show <drill-id>                    one drill's checks and error

A drill proves a restore works. A failed drill exits non-zero.
```

## levelrail-cli backups encryption

Subcommands: get, set

```
Usage:
  levelrail-cli backups encryption get <destination> [flags]
  levelrail-cli backups encryption set <destination> on|off [flags]

Shows or changes whether new database dumps sent to a backup destination are
encrypted with age. Existing dumps are never rewritten: old unencrypted dumps
stay as they are and still restore. Changing the setting needs a root token.
Losing the backup encryption key means encrypted backups cannot be restored. Keep a copy of backup-encryption.key off this machine.
```

## levelrail-cli backups orphans

Subcommands: list, reclaim

```
Usage:
  levelrail-cli backups orphans list [flags]                          data kept after its database or app was deleted
  levelrail-cli backups orphans reclaim <volume> --confirm <volume>   delete that data for good (destructive)

Nothing is ever removed automatically. Reclaiming needs the volume name typed
again as --confirm and a token with write:sensitive.
```

## levelrail-cli backups schedule

Subcommands: clear, pause, resume, set

```
Usage:
  levelrail-cli backups schedule set <database> --target ID --cron EXPR [flags]   configure a recurring backup
  levelrail-cli backups schedule clear <database> [flags]                        remove a recurring backup
  levelrail-cli backups schedule pause <database> [flags]                        stop running it, keep the config
  levelrail-cli backups schedule resume <database> [flags]                       run it again

Run "levelrail-cli backups schedule <subcommand> -h" for a subcommand's own flags.

## levelrail-cli backups volumes

Subcommands: list, policy, restore

```
Usage:
  levelrail-cli backups volumes list <app> <volume> [flags]       backup history of one app volume
  levelrail-cli backups volumes policy get <app> <volume>         show retention counts and hooks
  levelrail-cli backups volumes policy set <app> <volume> [--retain-daily N --retain-weekly N --retain-monthly N --pre-hook CMD --post-hook CMD --clear-pre-hook --clear-post-hook --pause|--no-pause]
  levelrail-cli backups volumes restore <app> <volume> --backup ID [--new-volume|--new-volume-name NAME] [--target-app APP] [--node NODE]
                                                         restore into a NEW volume (never overwrites), optionally for another app or on another node
To run one volume backup now: levelrail-cli app-volume-backups trigger <app> <volume> --target ID
To check that a backup restores: levelrail-cli app-volume-backups verify <app> <volume> (see "levelrail-cli app-volume-backups --help")
Policy set merges: flags you omit keep the stored value. Clear a hook with --clear-pre-hook or --clear-post-hook.
```
