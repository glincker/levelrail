## levelrail-cli import

Subcommands: config, cutover, k8s, platform, repo, takeover, vercel

```
Usage:
  levelrail-cli import <repo-url|image> [flags]
  levelrail-cli import -f compose.yaml|Dockerfile [flags]
  levelrail-cli import --docker-run "docker run -p 80:80 nginx:1" [flags]
  levelrail-cli import k8s -f <file|-> [--dry-run] [--force]          convert Kubernetes manifests into apps, see "levelrail-cli import k8s -h"
  levelrail-cli import config [dir] [--out FILE] [--strict]            offline preview of Procfile, app.json and vercel.json as an app spec
  levelrail-cli import config|platform ... --emit stack --out DIR   write Stack, App, Database and Domain documents plus a secrets checklist for review
  levelrail-cli import repo plan <repo-url> [--branch B] [--dir D]   proposed app per monorepo package, nothing created
  levelrail-cli import repo apply <repo-url> [flags]                 create one app per monorepo package

Classifies the input (GitHub, GitLab, Gitea or Bitbucket repo URL, docker
run command, image reference, docker-compose.yml or Dockerfile) and prints
a deployment plan. Nothing is created unless --deploy is given.

Flags:
  -f, --file string     read a compose file or Dockerfile (- for stdin)
  --docker-run string   a docker run command to import
  --deploy              create the app and deploy it
  --analyze             analyze a repository: stack, build, port, health, env keys, databases, with evidence
  --apply               analyze, then create the databases, app, repository link and first build
  --base-directory DIR  monorepo app directory override (with --analyze or --apply)
  --dockerfile PATH     Dockerfile path override (with --analyze or --apply)
  --build-type TYPE     dockerfile, railpack or static (with --analyze or --apply)
  --no-database         with --apply, skip the suggested databases
  --name string         app name (default derived from the source)
  --ref string          git branch for a repo import
  --port int            container port override
  --env KEY=VALUE       env value, repeatable; required variables with no value block --deploy
  --token, --api-url, --profile, --json, --output, --query   as for every command
  -h, --help            show this help
```

## levelrail-cli import cutover

Subcommands: confirm-dns, plan, rollback, run, status

```
Usage:
  levelrail-cli import cutover plan     --session ID --app NAME [--json]
  levelrail-cli import cutover run      --session ID --app NAME --dry-run [--no-wait]
  levelrail-cli import cutover run      --session ID --app NAME --confirm NAME [--accept-warnings] [--no-wait]
  levelrail-cli import cutover status   --session ID --app NAME [--run ID] [--json]
  levelrail-cli import cutover rollback --session ID --app NAME [--run ID]
  levelrail-cli import cutover confirm-dns --session ID --app NAME [--run ID]

A guided, reversible cutover of one staged app. plan prints the readiness
checklist (image, env, database, volumes, health, DNS). run --dry-run starts
the app, waits for it to be healthy and probes it through this node's
ingress, then stops it again without changing any record. run --confirm
does the same, then switches traffic (a DNS record through a connected
provider with the previous value stored, the managed proxy route, or a
record you set by hand), verifies the public name and rolls back on its own
if verification fails. The source platform is never written to.

Flags:
  --wait DURATION   how long run waits for the run to settle (default 20m)
  --api-url URL     control plane API base URL
  --profile NAME    named credentials profile for the control plane
```

## levelrail-cli import platform

Subcommands: caprover, coolify, dokploy

```
Usage:
  levelrail-cli import platform coolify|dokploy|caprover|heroku|vercel|render --url URL [flags]

Reads apps, databases and settings from another platform (read-only) and
creates them here. Use --dry-run first. Databases and volumes are created
empty, data is not migrated. Re-running skips what was already imported.

The source token (Coolify API token, Dokploy API key, CapRover password, Heroku API token, Vercel token, Render API key) is
read from APP_IMPORT_SOURCE_TOKEN, or --token-stdin, or --token (warns: it lands in shell
history). It is sent to this control plane in the request body only and is
never stored.

Flags:
  --url string          source platform base URL (required, Heroku, Vercel and Render default to their public API)
  --dry-run             report only, create nothing
  --only string         comma-separated source ids or names to import
  --collision string    suffix (default) or skip when a name is taken
  --db-version string   engine version for databases the source reports none for (postgres=16,redis=7.4)
  --team string         Vercel only: team id (team_...) or slug, default is the personal account
  --insecure-tls        skip TLS verification of the source
  --allow-private       allow a private-network source (control plane also needs APP_IMPORT_ALLOW_PRIVATE_NETWORKS=true)
  --allow-loopback      allow a loopback source (control plane also needs APP_IMPORT_ALLOW_LOOPBACK=true)
  --token-stdin         read the source token from stdin
  --api-url string      control plane API base URL
  --profile string      named credentials profile for the control plane
  --json                print the report as JSON
  --emit stack          write reviewable documents instead of creating anything here
                        (reads the source only, needs no control plane); also needs --out
  --out DIR             with --emit: the directory to write into
  --stack NAME          with --emit: stack name (default PLATFORM-import)
  --project NAME        with --emit: project name (default: the stack name)
  --environment NAME    with --emit: also write an Environment and place the apps in it
  --image-repo REPO     with --emit: image path for apps with no image, as REPO/APP:latest
  --force               with --emit: overwrite files already in DIR

With --emit stack the output is a Stack, Project, Database, App and Domain
documents plus SECRETS.md (secret names only, never values) and MIGRATION.md.
Review them in a pull request, then run stack plan and stack apply.

Delete imported resources by label: apps carry import/source-id.
```

## levelrail-cli import takeover

Subcommands: plan, rollback, run, status

```
Usage:
  levelrail-cli import takeover plan     [--accept-unmanaged] [--json]
  levelrail-cli import takeover run      --dry-run [--accept-unmanaged] [--json]
  levelrail-cli import takeover run      --confirm takeover [--accept-unmanaged] [--no-wait] [--wait DURATION] [--json]
  levelrail-cli import takeover status   [--run ID] [--json]
  levelrail-cli import takeover rollback [--run ID] [--reason TEXT] [--no-wait] [--wait DURATION] [--json]

Moves this server's ports 80 and 443 from the proxy of the platform you are
migrating off (Coolify's Traefik, Caddy or nginx) to the built-in ingress.
plan prints the preflight (who holds the ports, apps healthy, DNS, certificates,
headroom) and the exact steps, and changes nothing; run --dry-run is the same.
run --confirm takeover records the way back, stops the old proxy container
(stopped, never removed), lets this server terminate TLS, stores the new listen
addresses, restarts the control plane and verifies every domain over HTTPS. If
verification does not succeed within APP_TAKEOVER_WINDOW (default 5m) it rolls
back by itself. rollback restores the previous addresses and TLS settings and
starts the old proxy again. Root only. Common flags: --api-url, --profile.
```
