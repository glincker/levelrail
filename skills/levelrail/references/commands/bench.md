## levelrail-cli bench

Subcommands: chaos, results, run, soak

```
Usage: levelrail-cli bench run --url URL [flags]

Open-loop load run (constant arrival rate, latency measured from the intended
send time) against an app served through the ingress.

  --url URL                 app URL through the ingress (required)
  --direct-url URL          one replica without the ingress, for the overhead comparison
  --rate N                  requests per second (default 100)
  --duration D              measured run length (default 30s)
  --baseline-duration D     direct run length (default 10s)
  --timeout D               per-request timeout (default 5s)
  --event-at D              when the scenario fires (default one third into the run)

One failure scenario at most:
  --kill-replica-url URL    POST a replica's fixture /__bench/die mid-run
  --drain-node ID           drain a node mid-run, with --drain-target ID
  --restart-control-plane   restart the control plane mid-run

  --hardware TEXT           server hardware note stored in the report
  --json                    print the report as JSON to stdout and nothing else

Related: "bench chaos" runs the failure scenarios, "bench results" lists and
compares stored runs, "bench soak" holds load and samples the footprint.
```

## levelrail-cli bench chaos

Subcommands: disk, free-space, list, report, run

```
Usage: levelrail-cli bench chaos <list|run|report|disk|free-space> [flags]

Failure and performance scenarios measured against throwaway local Docker
containers (unique name prefix, always removed afterwards). Never run against a
remote server: the scenarios build their own local stack. Scenarios include
deploy-latency, rollout-under-traffic, ingress-concurrency and replica-failover.

  list                 the scenarios and the behaviour each one asserts
  run <scenario...|all>  run live (needs a build with -tags chaoslive and a local
                       Docker daemon); prints a table, or JSON with --json
  report               the latest recorded results from the control plane
  disk                 free space on the data and Docker volumes, and whether risky operations are refused
  free-space           run a forced cleanup pass now (the fix for a low-disk refusal), needs a root token

  --record             run: store the results on the control plane
  --hardware TEXT      run: hardware note kept in each result
  --markdown           run: print the results as a Markdown table
  --out FILE           run: write the structured results file (JSON) with host, build, method and limits
  --md-out FILE        run: write the rendered Markdown report
  --upload             run: upload the structured results to the control plane (dashboard, bench results compare)
  --repeat N           run: run each scenario N times and keep every run (default 1)
  --json               print machine-readable output only

Exit code 2 when any scenario assertion failed.
```

## levelrail-cli bench results

Subcommands: compare, delete, list, show, upload

```
Usage: levelrail-cli bench results <list|show|compare|upload|delete> [flags]

Benchmark results files stored on the control plane, produced by
"bench chaos run --out FILE" (or uploaded directly with --upload).

  list                     stored runs, newest first (--limit N)
  show ID                  one run: host, build, caveats, per-scenario numbers, limits table
  compare BASE HEAD        every metric of two runs with deltas (median over runs on each side)
  upload FILE              store a results file
  delete ID                remove a run (needs a root token)

Results from a non-Linux host are never Linux production numbers; compare says so.
  --json                   print machine-readable output only
```
