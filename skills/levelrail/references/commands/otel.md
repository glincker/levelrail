## levelrail-cli otel

Subcommands: destinations

```
Usage:
  levelrail-cli otel destinations list [flags]                    list OTLP destinations and their delivery state
  levelrail-cli otel destinations add --name N --endpoint U [--signal metrics|logs] [flags]
                                                          add an OTLP/HTTP destination (default signal: metrics)
  levelrail-cli otel destinations test <id> [flags]               send one probe and report the result
  levelrail-cli otel destinations remove <id> [flags]             delete a destination and its stored headers

Add accepts the same flags as "levelrail-cli export destinations create -h" (--app, --header, --label, --interval,
--min-level for logs). Header values are stored encrypted and never shown again. Nothing is exported until
a destination exists, and collection stays pull-based on the node.
```
