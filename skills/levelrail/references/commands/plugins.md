# levelrail-cli plugins

Generated by `levelrail-cli docs`. Do not edit.

## levelrail-cli plugins

Subcommands: approve, disable, dns-provider, enable, inspect, install, list, marketplace, remove, restart, run, show, test, trust, uninstall, upgrade

```
Usage:
  levelrail-cli plugins list [flags]                              list installed plugins
  levelrail-cli plugins show <name> [flags]                       show one plugin, its requested and approved abilities
  levelrail-cli plugins inspect (--manifest FILE | --url URL) [--signature FILE] [flags]
                                                          verify a package and show its abilities and what would change, installs nothing
  levelrail-cli plugins install (--manifest FILE | --url URL) [--signature FILE] [--key-id ID] [--digest DIGEST] [--config FILE] [--approve ABILITIES] [flags]
                                                          verify and record a plugin; --approve must list exactly the requested abilities
  levelrail-cli plugins upgrade (--manifest FILE | --url URL) [same flags as install]
                                                          replace an installed plugin; wider abilities or hosts need a new approval
  levelrail-cli plugins approve <name> --abilities read[,read:sensitive] [flags]
                                                          grant the listed abilities, never implied by install
  levelrail-cli plugins enable|disable|restart <name> [flags]     start, stop or restart a plugin (restart clears failure backoff)
  levelrail-cli plugins uninstall|remove <name> [flags]           stop and delete a plugin
  levelrail-cli plugins test <name> [flags]                       check a dns_provider plugin can reach its provider with the stored credential
  levelrail-cli plugins dns-provider [<name> | --off] [flags]     show or choose the dns_provider plugin that writes DNS records (default: built-in client)
  levelrail-cli plugins run <plugin> <command> [--app NAME] [flags]
                                                          run a command the plugin declares in its manifest (shows data or presses a button)
  levelrail-cli plugins trust add --name NAME --public-key B64 [flags]   trust a publisher's ed25519 public key
  levelrail-cli plugins trust list|remove <key-id> [flags]        show or revoke trusted keys
  levelrail-cli plugins marketplace search|info|install|update|refresh|sources ...
                                                          browse and one-step install from signed indexes (run it with no arguments for details)

Managing plugins needs the plugins experimental feature and a root token. Running a
plugin command needs read (data commands) or write:sensitive (buttons) and reaches only what the
operator approved. Nothing third party
loads until a key is trusted: the default trust list is empty.
```

## levelrail-cli plugins marketplace

Subcommands: info, install, refresh, search, sources, update

```
Usage:
  levelrail-cli plugins marketplace search [QUERY] [--category C] [flags]      list plugins from the signed marketplace indexes
  levelrail-cli plugins marketplace info ID [--source SRC] [flags]             show what installing would do: publisher key, abilities, digest
  levelrail-cli plugins marketplace install ID --approve-abilities LIST --yes [--trust-publisher] [--source SRC] [flags]
                                                                      trust, install, approve exactly LIST and enable in one step
  levelrail-cli plugins marketplace update (NAME | --all) --approve-abilities LIST --yes [flags]
                                                                      upgrade installed plugins that have a newer signed listing
  levelrail-cli plugins marketplace refresh [--source SRC] [flags]            refetch and re-verify the indexes
  levelrail-cli plugins marketplace sources list [flags]                      show index sources and their last status
  levelrail-cli plugins marketplace sources add --url URL --root-key B64 [--name NAME] [flags]
  levelrail-cli plugins marketplace sources remove ID [flags]

--approve-abilities must list exactly the abilities that info shows, never fewer or more.
Nothing is installed without --yes, and an untrusted publisher key needs --trust-publisher.
```
