## levelrail-cli logs

Subcommands: access, alert-from, archive, dump, failure, fetch, ls, query, saved, search, signatures, usage

```
Usage:
  levelrail-cli logs <app> [flags]                     an app's recent logs, the same as "apps logs <app>"
  levelrail-cli logs usage                             stored log volume per app, noisiest first, with budget and forecast
  levelrail-cli logs archive set --target ID [--app NAME] [--interval 1h] [--retention-days N] [--disable]
  levelrail-cli logs archive status                    show every archive policy and its last run
  levelrail-cli logs archive remove [--app NAME]       stop archiving (all apps when --app is omitted)
  levelrail-cli logs dump --target ID --from TIME [--to TIME] [--app NAME] [--wait]   archive a time range now
  levelrail-cli logs ls --target ID [--app NAME]       list archived objects
  levelrail-cli logs fetch --target ID --key KEY [--out FILE]   download one archived object (gzip NDJSON)
  levelrail-cli logs query <app> [--level L] [--since 30m] [--deploy ID] [--text T] [--max-lines N]   capped excerpt of the newest matching lines
  levelrail-cli logs search <app> [--q T] [--level L] [--container ID] [--stream S] [--field k=v]... [--since 1h] [--limit N]   full text and structured field search
  levelrail-cli logs failure <app>                     last 200 lines of the crashlooping container or the failed deploy
  levelrail-cli logs access [--app A] [--status 5xx] [--path /p] [--q T] [--since 1h]   search recent HTTP requests at the edge
  levelrail-cli logs signatures <app> [--since 24h] [--new]   top clusters of similar error lines
  levelrail-cli logs saved list|create|run|delete       named searches, optionally shared or pinned to an app
  levelrail-cli logs alert-from <app> --name N (--count N | --per-minute R) [filters]   alert rule from a search

TIME is an RFC3339 timestamp or a duration back from now such as 24h.
Without --app, a policy or dump covers every app.

Common flags:
  --token string     API token (default: the credentials file or the API token env var)
  --api-url string   control plane base URL
  --profile string   named credentials profile
  --json             print the result as JSON and nothing else
  --output string    json, table, or text
  --query string     JMESPath expression applied to the result
```

## levelrail-cli logs saved

Subcommands: create, delete, list, run

```
levelrail-cli: unknown logs saved subcommand "--help"

Usage:
  levelrail-cli logs signatures <app> [--since 24h | --from T --to T] [--level error] [--q T] [--limit 25] [--new]
  levelrail-cli logs saved list [--app NAME]
  levelrail-cli logs saved create <name> [--app NAME] [--q T] [--level L] [--stream S] [--field k=v]... [--range 1h] [--share] [--pin]
  levelrail-cli logs saved run <id> [--limit N]
  levelrail-cli logs saved delete <id>
  levelrail-cli logs alert-from <app> --name NAME (--count N | --per-minute R) [--q T] [--regex RE] [--level L] [--field k=v]...
        [--window 5m] [--cooldown 15m] [--severity S] [--channel ID | --notify-url URL --notify-kind K]

signatures clusters similar error lines (numbers, ids and timestamps are
normalised away) and prints the top clusters with counts. --new compares with
the window of equal length just before and marks clusters that are new.
alert-from creates a log_pattern rule (--count) or a log_level_rate rule
(--per-minute) from the same filters "logs search" takes.

Common flags:
  --token string     API token (default: the credentials file or the API token env var)
  --api-url string   control plane base URL
  --profile string   named credentials profile
  --json             print the result as JSON and nothing else
  --output string    json, table, or text
  --query string     JMESPath expression applied to the result
```
