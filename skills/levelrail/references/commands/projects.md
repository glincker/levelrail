## levelrail-cli projects

Subcommands: backfill-default-env, create, delete, env-get, env-set, export, get, import, list, restart, show, start, stop, topology

```
Usage:
  levelrail-cli apps projects create --name NAME [flags]        create a project
  levelrail-cli apps projects list [flags]                         list projects
  levelrail-cli apps projects get <id> [flags]                     show one project
  levelrail-cli apps projects delete <id> [flags]                  delete a project
  levelrail-cli apps projects stop <id> [flags]                    stop every app and database in a project
  levelrail-cli apps projects start <id> [flags]                   start every app and database in a project
  levelrail-cli apps projects restart <id> [flags]                 restart every app in a project
  levelrail-cli apps projects env-get <id> [flags]                 show a project's shared env vars
  levelrail-cli apps projects env-set <id> --var KEY=VALUE [flags]   replace a project's shared env vars
  levelrail-cli apps projects topology <id> [flags]                diagram-ready graph of a project's apps, databases, and volumes
  levelrail-cli apps projects export <name> [-o DIR|-] [flags]     write a project as plain docker-compose.yml, .env.example and volumes.json
  levelrail-cli projects export <name> --out FILE.lrx [--include-data] [--include-secrets]   write a project archive
  levelrail-cli projects import FILE.lrx [--plan] [--rename NAME]  create a project from an archive

A project groups apps and databases (move one in with "levelrail-cli apps
set-project" or "levelrail-cli databases set-project"); deleting a project
leaves its members running, simply project-less again. File a project
under an organization with "levelrail-cli apps organizations set-project". Its
shared env vars sit between its organization's own shared env vars and
any of its environments' shared env vars.

Run "levelrail-cli apps projects <subcommand> -h" for a subcommand's own flags.
```
