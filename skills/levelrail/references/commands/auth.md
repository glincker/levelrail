## levelrail-cli auth

Subcommands: 2fa, activity, approve, code, code-login, delete-account, deny, devices, email-change, export, login, passkeys, preferences, session-link, sign-in-requests, status, trust-server, unlink, whoami

```
Usage:
  levelrail-cli auth login [flags]           authenticate and persist a new API token
  levelrail-cli auth whoami [flags]          show who the current token authenticates as
  levelrail-cli auth status [flags]          show the server this profile is pinned to and check it
  levelrail-cli auth trust-server [flags]    pin the server at the profile's URL (after confirming its fingerprint)
  levelrail-cli auth 2fa <verb>             manage this account's own two-factor authentication
  levelrail-cli auth passkeys <verb>        list, rename or remove this account's passkeys
  levelrail-cli auth session-link [flags]    mint a short-lived, single-use login link
  levelrail-cli auth code [flags]            show sign-in codes and new-browser sign-ins waiting for you
  levelrail-cli auth approve <id>            approve a new-browser sign-in
  levelrail-cli auth deny <id>               deny a new-browser sign-in
  levelrail-cli auth devices [revoke <id>]   list or revoke browsers trusted for password sign-in
  levelrail-cli auth devices trusted list|revoke  the same, as list and revoke (revoke asks first)
  levelrail-cli auth sign-in-requests list|reveal  list waiting sign-ins, or print one code once
  levelrail-cli auth code-login [flags]      show or change the auth.code_login setting
  levelrail-cli auth activity [flags]        show your own account activity feed
  levelrail-cli auth preferences get|set     your timezone, language, theme, landing page and avatar
  levelrail-cli auth export [flags]          download a zip of your own account data
  levelrail-cli auth unlink <provider>       remove a linked sign-in provider
  levelrail-cli auth email-change request|confirm  change your account email
  levelrail-cli auth delete-account [flags]  permanently delete your own account

Run "levelrail-cli auth <subcommand> -h" for a subcommand's own flags.
```

## levelrail-cli auth 2fa

Subcommands: disable, enable, recovery-codes, setup, status

```
Usage:
  levelrail-cli auth 2fa status [flags]                                          show whether two-factor auth is enabled
  levelrail-cli auth 2fa setup [flags]                                             start enrollment, returns a secret and provisioning URI
  levelrail-cli auth 2fa enable --code CODE [flags]                          confirm enrollment, returns recovery codes once
  levelrail-cli auth 2fa disable --code CODE|--recovery-code CODE [flags]   turn two-factor auth off
  levelrail-cli auth 2fa recovery-codes --code CODE [flags]                regenerate recovery codes, invalidating the old set

Every subcommand here requires a live session: --username/--password
(prompted if omitted), same as "levelrail-cli tokens" and "levelrail-cli auth login", never
this CLI's own persisted bearer token.

Run "levelrail-cli auth 2fa <subcommand> -h" for a subcommand's own flags.
```

## levelrail-cli auth devices

Subcommands: revoke, trusted

```
Usage:
  levelrail-cli auth devices [flags]
  levelrail-cli auth devices revoke <device-id> [flags]

Lists the browsers trusted to sign in to your account with a password
without approval, or revokes one so its next sign-in needs approval again.

Flags:
  -api-url string
    	control plane API base URL (overrides LEVELRAIL_API_URL or APP_API_URL and the credentials file, default http://localhost:8080)
  -json
    	print the devices as JSON
  -output string
    	output format: json, table, or text (default table; --json is shorthand for --output json)
  -profile string
    	named credentials profile to read (overrides APP_PROFILE, default "default")
  -query string
    	JMESPath expression to filter the result before printing (e.g. "[?status=='running'].name")
  -token string
    	API token (overrides LEVELRAIL_TOKEN or APP_API_TOKEN and the credentials file)
```

## levelrail-cli auth devices trusted

Subcommands: list, revoke

```
Usage:
  levelrail-cli auth devices trusted list [flags]               list browsers trusted for password sign-in
  levelrail-cli auth devices trusted revoke <id> [--yes] [flags] revoke one; its next sign-in needs approval again

A trusted browser signs in to your account with a password without a new
browser approval. The token must belong to your user.
```

## levelrail-cli auth sign-in-requests

Subcommands: list, reveal

```
Usage:
  levelrail-cli auth sign-in-requests list [flags]           waiting sign-in codes and new-browser sign-ins, no code shown
  levelrail-cli auth sign-in-requests reveal <code-id> [flags] print one waiting sign-in code, once

Listing needs write:sensitive or signin:approve. reveal prints the code to
stdout only; it is never saved. Only use a code if you started that sign-in.

Revealing a code or approving a browser needs a token that belongs to your
user and holds signin:approve. No device login token, root token or
write:sensitive token carries it. Approving or denying a waiting browser
also accepts your own unscoped root token (type the number it shows).
Mint an approver while signed in with your password, or use the dashboard:
  levelrail-cli tokens create --name approver --abilities signin:approve --expires-in-days 30
```
