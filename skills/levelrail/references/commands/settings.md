## levelrail-cli settings dashboard-url

Subcommands: fix, get, set

```
Usage:
  levelrail-cli settings dashboard-url get [flags]
  levelrail-cli settings dashboard-url set --url URL [flags]
  levelrail-cli settings dashboard-url fix [flags]

fix switches the URL to https on the primary domain once that domain
answers over https with a valid certificate. It moves passkeys and OAuth
callbacks to the https host.

The public URL operators use to reach the dashboard. Once it is https,
sign-in over plain HTTP is refused (set APP_ALLOW_INSECURE_LOGIN=true on
the control plane to recover). Pass --url "" to clear it.
```

## levelrail-cli settings ddns

Subcommands: disable, enable, set, show, status

```
Usage:
  levelrail-cli settings ddns show [flags]
  levelrail-cli settings ddns set [--provider generic|duckdns] [--domains LIST] [--target URL|TOKEN | --clear-target] [tuning flags] [flags]
  levelrail-cli settings ddns enable|disable [flags]
  levelrail-cli settings ddns status [flags]

Keeps a DNS record pointed at this host's public IPv4. The stored setting
wins and applies at once, no restart; APP_DDNS_* env values are only the
defaults used until something is stored.

The target (generic: an update URL containing {ip}; duckdns: the token) is
stored encrypted and only its host is shown. Pass --target - to read it from
stdin, or set LEVELRAIL_DDNS_TARGET, to keep it out of shell history. --clear-target removes
the stored target; an empty --target is refused so a clear is never silent.

Tuning flags: --interval, --timeout, --min-update-gap, --reassert (durations
like 5m), --probe-urls (comma list), --probe-quorum, --fail-alert-after,
--allow-private on|off, --allow-insecure-http on|off.

Flags:
  --token string       API token (default: LEVELRAIL_TOKEN or APP_API_TOKEN env var, then the credentials file)
  --api-url string     control plane base URL (default: LEVELRAIL_API_URL or APP_API_URL env var, then http://localhost:8080)
  --profile string     named credentials profile to read
  --json               print the result as JSON to stdout, nothing else
  -h, --help           show this help
```

## levelrail-cli settings deploy-freeze

Subcommands: clear, set, show

```
Usage:
  levelrail-cli settings deploy-freeze show [flags]
  levelrail-cli settings deploy-freeze set --cron EXPR --duration D [--timezone TZ] [--reason TEXT] [flags]
  levelrail-cli settings deploy-freeze clear [flags]

Fleet-wide deploy freeze windows: every app's own windows (see
"apps freeze") inherit these on top. A freeze window starts at every
match of a 5-field cron expression, evaluated in --timezone (default
UTC), and lasts --duration. While one is active, webhook, pipeline and
released deploys are held fleet-wide and run automatically when the
window ends; manual deploys need
"apps deploy --override-freeze --override-reason TEXT". "set" replaces
the fleet-wide windows with the one given.

Example, a weekend freeze in Berlin:
  levelrail-cli settings deploy-freeze set --cron "0 17 * * 5" --duration 64h --timezone Europe/Berlin --reason weekend

Flags:
  --token string          API token (default: LEVELRAIL_TOKEN or APP_API_TOKEN env var, then the credentials file)
  --api-url string       control plane base URL (default: LEVELRAIL_API_URL or APP_API_URL env var, then http://localhost:8080)
  --profile string       named credentials profile to read
  --json                    print the result as JSON to stdout, nothing else
  -h, --help               show this help
```

## levelrail-cli settings deploy-url-copies

Subcommands: get, set

```
Usage:
  levelrail-cli settings deploy-url-copies get [flags]
  levelrail-cli settings deploy-url-copies set <off|private|public|default> [flags]

Whether recent deploys keep a retained copy, and whether it is reachable.
  off      no copies are kept
  private  copies are kept suspended with no public host or certificate (default)
  public   copies get their own hostname and certificate, the pre-0.9 behavior
  default  clear the stored value; APP_DEPLOY_URL_COPIES, then private, applies

A stored value wins over the environment. It applies on the next sync pass,
without a restart.
```

## levelrail-cli settings email branding

Subcommands: get, preview, set

```
Usage:
  levelrail-cli settings email branding get [flags]
  levelrail-cli settings email branding set [branding flags]
  levelrail-cli settings email branding preview [branding flags]

Branding is shared by every rich email. The logo is an https URL that the
server never fetches; a remote logo tells its host when a message is opened.
The footer is plain text plus https links (no HTML). Footer text accepts the
global variables such as {{brand_name}} and {{year}}.

Branding flags (only the ones you pass change; the rest keep their saved value):
  --logo-url URL            https logo, or "" to clear
  --brand-color HEX         accent color such as #107292, or "" for the brand default
  --footer-text TEXT        footer message
  --footer-address TEXT     postal address line
  --footer-link "Label|URL" repeatable https footer link (replaces the saved list)
  --clear-footer-links      remove every footer link
  --powered-by[=false]      show or hide the "Powered by" line

"preview" renders the result around a sample message without saving it and
prints the HTML (or the full response with --json).
```

## levelrail-cli settings email providers

Subcommands: add, list, promote, reveal, rm, set, test

```
Usage:
  levelrail-cli settings email providers list [flags]
  levelrail-cli settings email providers add --backend smtp|ses|ses_smtp|resend|postmark|sendgrid|mailgun [flags]
  levelrail-cli settings email providers set <id> [flags]
  levelrail-cli settings email providers rm <id> [flags]
  levelrail-cli settings email providers test <id> [--to ADDRESS] [flags]
  levelrail-cli settings email providers promote <id> [flags]
  levelrail-cli settings email providers reveal <id> <field> --yes-print [flags]

One primary provider plus at most one backup. The first provider added is the
primary, the second the backup. When the primary fails before a message is
accepted, sending falls over to the backup. "promote" swaps the two roles.

Credentials are never passed as arguments. "add" prompts for the credential when
stdin is a terminal; "--secret-stdin" reads it from the first line of stdin, and
"--prompt-secret" forces the prompt. On "set", the stored credential is kept unless
one of those flags is given. The credential that applies is the one for the backend
(SMTP password, SES secret access key, API key or token).

"reveal" prints one stored credential after asking for your password and
authenticator code at the terminal. It needs two-factor authentication on your
account, is rate limited and is audited. It refuses unless --yes-print is given,
because the value goes to stdout.

Run "levelrail-cli settings email providers <subcommand> -h" for a subcommand's own flags.
```

## levelrail-cli settings heartbeat

Subcommands: clear, set, show

```
Usage:
  levelrail-cli settings heartbeat show [flags]
  levelrail-cli settings heartbeat set --url URL [--fail-url URL] [--body on|off] [--agent-silence-url URL] [flags]
  levelrail-cli settings heartbeat clear [--agent-silence] [flags]

An outbound dead-man ping: while the control plane is healthy it calls the
URL every interval, so an external monitor (Healthchecks, Uptime Kuma push,
Better Stack) alerts when the pings stop. The URL holds a secret key, so
it is stored encrypted and only its host is ever shown. Pass --url - to
read it from stdin and keep it out of shell history.

Agents that lose the control plane for the grace period (APP_AGENT_CP_SILENCE_GRACE
on the agent, default 5m) ping --agent-silence-url, so a dead control plane is
noticed even when the box is up. Use your monitor's failure endpoint.

Flags:
  --url string         ping URL (write-only)
  --fail-url string    optional URL called instead when the control plane knows it is unhealthy
  --agent-silence-url string  URL every agent pings while it cannot reach the control plane (write-only, - reads stdin)
  --agent-silence      with clear: remove only the agent silence URL
  --body string        send a small status JSON body: on or off
  --token string       API token (default: LEVELRAIL_TOKEN or APP_API_TOKEN env var, then the credentials file)
  --api-url string     control plane base URL (default: LEVELRAIL_API_URL or APP_API_URL env var, then http://localhost:8080)
  --profile string     named credentials profile to read
  --json               print the result as JSON to stdout, nothing else
  -h, --help           show this help
```

## levelrail-cli settings ingress cloudflare

Subcommands: set, show

```
Usage:
  levelrail-cli settings ingress cloudflare show [flags]
  levelrail-cli settings ingress cloudflare set --preset none|cloudflare [--confirm-weakening] [flags]

With cloudflare, the visitor address comes from CF-Connecting-IP, but only when the
connection arrives from Cloudflare's published ranges. Any Cloudflare customer can
reach your server through their own proxied record, so this is not proof a request
came through your zone. The stored value wins and applies at once; the range list is
refreshed in the background (see settings runtime, ingress.cloudflare_ips_*).

Flags:
  -api-url string
    	control plane API base URL (overrides LEVELRAIL_API_URL or APP_API_URL and the credentials file, default http://localhost:8080)
  -confirm-weakening
    	required to switch to cloudflare, which trusts CF-Connecting-IP from Cloudflare's ranges
  -json
    	print the result as JSON to stdout and nothing else
  -output string
    	output format: json, table, or text (default table; --json is shorthand for --output json)
  -preset string
    	none or cloudflare (set only)
  -profile string
    	named credentials profile to read (overrides APP_PROFILE, default "default")
  -query string
    	JMESPath expression to filter the result before printing (e.g. "[?status=='running'].name")
  -token string
    	API token (overrides LEVELRAIL_TOKEN or APP_API_TOKEN and the credentials file)
```
