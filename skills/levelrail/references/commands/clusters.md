## levelrail-cli clusters

Subcommands: connect, deploy, deployments, disconnect, list, logs, namespaces, nodes, rbac, remove, show, status, test

```
Usage:
  levelrail-cli clusters connect <name> (--kubeconfig FILE | --server URL --token-file FILE [--ca-file FILE]) [--context C] [flags]
  levelrail-cli clusters list [flags]                 connected Kubernetes clusters
  levelrail-cli clusters show <name> [flags]          one cluster
  levelrail-cli clusters test <name> [flags]          read-only connection test
  levelrail-cli clusters nodes <name> [flags]         nodes with readiness and roles
  levelrail-cli clusters namespaces <name> [flags]    namespaces
  levelrail-cli clusters disconnect <name> [flags]    forget the stored credential
  levelrail-cli clusters deploy <name> --app A --image I --port N [--env-file F] [--replicas N] [--host H] [--namespace NS] [--allow-root]
  levelrail-cli clusters deployments <name> [flags]   apps deployed to a cluster
  levelrail-cli clusters status <name> <app> [flags]  rollout state, conditions and ingress address
  levelrail-cli clusters logs <name> <app> [--tail N] [--pod P] [flags]  tail the logs of a deployed app
  levelrail-cli clusters remove <name> <app> [--yes]  delete the app's Deployment, Service and Ingress (the namespace stays)
  levelrail-cli clusters rbac --namespace NS [--cluster-read] [flags]  print a namespace-scoped ServiceAccount, Role and RoleBinding (--cluster-read adds a read-only ClusterRole for nodes and namespaces)

Credentials come from a file, or "-" for stdin, never from an argument.
```
