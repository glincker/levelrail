## levelrail-cli apps abuse

Subcommands: dry-run, get, set

```
Usage:
  levelrail-cli apps abuse get <app> [flags]        show the policy, its status and what it counted lately
  levelrail-cli apps abuse set <app> [flags]        change the policy; a flag changes only its own field
  levelrail-cli apps abuse dry-run <app> [flags]    replay recent traffic against the saved or a draft policy

set and dry-run flags:
  --mode off|log_only|enforce   log_only counts what would be blocked and blocks nothing (default off)
  --rps N                       sustained requests per second per client IP, 0 turns the limit off
  --burst N                     bucket size (default two seconds of --rps)
  --deny-cidr LIST              comma separated IPs or CIDR ranges to turn away, "none" clears the list
  --deny-agent LIST             comma separated User-Agent substrings to turn away, "none" clears the list
  --require-user-agent=BOOL     turn away requests with no User-Agent
  --suggested                   start from the suggestion for this app's recent peak (set, dry-run)

dry-run flags:
  --minutes N                   how far back to replay (default from the instance)

Exceeding the limit answers 429 with Retry-After. Move from log_only to
enforce once dry-run shows nothing you want to keep would be blocked. The
control plane keeps recent requests in memory only, so a dry run covers what
it still holds.

Common flags:
  --token string     API token (default: the credentials file or the API token env var)
  --api-url string   control plane base URL
  --profile string   named credentials profile
  --json             print the result as JSON and nothing else
  --output string    json, table, or text
  --query string     JMESPath expression applied to the result
```

## levelrail-cli apps alerts

Subcommands: create, delete, list, slo, template, update

```
Usage:
  levelrail-cli apps alerts list <app> [flags]
  levelrail-cli apps alerts create <app> --kind threshold --metric METRIC --comparator OP --threshold N [flags]
  levelrail-cli apps alerts create <app> --kind crashloop --restart-count-threshold N --restart-window DURATION [flags]
  levelrail-cli apps alerts create <app> --kind cert_expiry [flags]
  levelrail-cli apps alerts create <app> --kind patch_status [flags]
  levelrail-cli apps alerts create <app> --kind scheduled_task_failure --scheduled-task-id ID --restart-count-threshold N [flags]
  levelrail-cli apps alerts create <app> --kind node_disk_space [flags]
  levelrail-cli apps alerts create <app> --kind node_resource_usage [flags]
  levelrail-cli apps alerts create <app> --kind node_offline [flags]
  levelrail-cli apps alerts create <app> --kind domain_health [flags]
  levelrail-cli apps alerts create <app> --kind control_plane_backup_stale [flags]
  levelrail-cli apps alerts create <app> --kind log_archive_stale [flags]
  levelrail-cli apps alerts create <app> --kind backup_missing --backup-resource-kind database --backup-database-name NAME [flags]
  levelrail-cli apps alerts create <app> --kind backup_missing --backup-resource-kind volume --backup-volume-name NAME [flags]
  levelrail-cli apps alerts create <app> --kind slo_burn --slo 99.9 [--slo-latency-ms N] [flags]
  levelrail-cli apps alerts slo <app> [--slo 99.9] [--slo-latency-ms N]
  levelrail-cli apps alerts template <app> [--profile-type web|worker|database] [--channel ID]
  levelrail-cli apps alerts update <app> <id> --kind KIND [flags]
  levelrail-cli apps alerts delete <app> <id> [flags]

Manages an app's alert rules. A threshold rule watches a metric; a
crashloop rule watches container restarts; a cert_expiry rule watches
every certificate on the whole control plane (not just this app's own
domains), a patch_status rule watches every node's pending OS security
patches the same way, a node_disk_space rule watches every node's disk
usage percentage the same way too, and a node_resource_usage rule
watches every node's summed CPU and memory usage the same way as well,
none of the four needing any metric/threshold/restart flags; a
scheduled_task_failure rule watches one of this app's scheduled tasks'
consecutive-failure count (see "apps scheduled-tasks list"), reusing
--restart-count-threshold as that count's threshold. A domain_health rule
watches this app's own configured domains for a DNS check gone bad (a
CNAME repointed away, a record missing entirely), needing no flags
either, though --for-duration optionally debounces a single blip. A
backup_missing rule watches one database's (--backup-database-name) or
one of this app's own volumes' (--backup-volume-name) scheduled backup
cadence and fires once its last successful backup trails that schedule's
own expected interval by more than --for-duration (reused here as the
overdue grace period, default 6h). A control_plane_backup_stale rule
watches the control plane's own newest snapshot platform-wide and fires
once it is older than --for-duration (default 3d); it stays quiet when
scheduled control plane backups are disabled. All ten notify the same
way once they fire.

Run "levelrail-cli apps alerts <subcommand> -h" for a subcommand's own flags.
```

## levelrail-cli apps auto-rollback

Subcommands: disable, enable, status

```
Usage:
  levelrail-cli apps auto-rollback enable <app-name> [flags]    opt an app into automatic rollback on a crashloop
  levelrail-cli apps auto-rollback disable <app-name> [flags]   opt an app back out
  levelrail-cli apps auto-rollback status <app-name> [flags]    show whether it's currently on

Off by default. Once enabled, the next time a kind=crashloop alert rule
fires for this app (see "apps alerts create --kind crashloop"), the
control plane automatically redeploys the most recent successful image
older than the one that's crashlooping, through the exact same trigger
path "apps rollback"/"apps deploy" use. Fires at most once per crashloop
episode; if there is no older successful image to fall back to, the app
is left to the crashloop alert alone rather than rolling back to nothing.

Run "levelrail-cli apps auto-rollback <subcommand> -h" for a subcommand's own flags.
```

## levelrail-cli apps auto-rollback-slo-burn

Subcommands: set, status

```
Usage:
  levelrail-cli apps auto-rollback-slo-burn set <app-name> <mode> [flags]   set how this app reacts to an SLO burn alert
  levelrail-cli apps auto-rollback-slo-burn status <app-name> [flags]       show the current mode

mode is one of:
  off               only alert, never act automatically (default)
  auto              roll back immediately to the most recent successful image
                    older than the one burning the error budget
  dry_run           log what would have been rolled back, never deploy
  pause_for_human   open a pending deploy approval instead of deploying
                    directly ("levelrail-cli deploy-approvals list")

Once set to auto or dry_run or pause_for_human, the next time a
kind=slo_burn alert rule fires for this app (see "apps alerts create
--kind slo_burn"), the control plane acts according to the chosen mode.
Fires at most once per firing episode; if there is no older successful
image to fall back to, the app is left to the alert alone.

Run "levelrail-cli apps auto-rollback-slo-burn <subcommand> -h" for a subcommand's own flags.
```

## levelrail-cli apps auto-update

Subcommands: check, disable, enable, status, webhook

```
Usage:
  levelrail-cli apps auto-update enable <app-name> [flags]    redeploy automatically when the image tag moves
  levelrail-cli apps auto-update disable <app-name> [flags]   opt back out
  levelrail-cli apps auto-update status <app-name> [flags]    show the setting and the last check
  levelrail-cli apps auto-update check <app-name> [flags]     check the registry now, redeploying if it moved
  levelrail-cli apps auto-update webhook <app-name> [flags]   mint a registry push webhook URL (shown once)

Point your registry's push webhook (Docker Hub, GitHub Packages for ghcr.io,
or any POST) at the webhook URL to update on push instead of waiting for the
interval. Docker Hub and GitHub pushes deploy the pushed digest; GitHub
deliveries are verified with the signing secret printed with the URL.

Use --window-cron and --window-minutes with enable to apply updates only inside
a window (UTC); one found earlier waits for it. --clear-window removes it.

Off by default. Enabled apps are checked on the control plane's interval
(APP_IMAGE_UPDATE_INTERVAL, default 1h). Apps built from source, stopped,
frozen, or in a protected environment are skipped, never forced.
```

## levelrail-cli apps autoscale

```
Usage:

  levelrail-cli apps autoscale clear <app-name> [flags]     remove the policy; replicas stay where they are

  --max N                     most replicas (required for a new policy)
```

## levelrail-cli apps watch

Subcommands: get, set, stop

```
Usage:
  levelrail-cli apps watch get <name> [flags]     post-deploy watch state and settings
  levelrail-cli apps watch set <name> [flags]     change the watch for this app ("default" clears one)
  levelrail-cli apps watch stop <name> [flags]    end the open watch of the newest release early

After a release takes traffic it is watched for --watch-window. A crashloop,
OOM kill, readiness failure or 5xx share over --watch-error-rate is a hard
signal: in mode auto the release is rolled back to the retained previous one,
in mode notify the alert channels are told. A p95 latency regression against
the previous release is a soft signal: it only notifies unless --soft-rollback
is true and the mode is auto. To roll back by hand use "levelrail-cli apps rollback".

Set flags:
  --mode MODE                 off, notify or auto
  --watch-window D            e.g. 10m
  --watch-max-restarts N      restarts that trip the watch
  --watch-error-rate F        5xx share between 0 and 1
  --watch-min-requests N      requests needed before a rate or latency counts
  --latency-ratio F           p95 multiple over the previous release, 0 is off
  --soft-rollback BOOL        let a latency regression roll back in auto mode

Flags:
  --token string          API token (default: LEVELRAIL_TOKEN or APP_API_TOKEN env var, then the credentials file)
  --api-url string       control plane base URL (default: LEVELRAIL_API_URL or APP_API_URL env var, then http://localhost:8080)
  --profile string       named credentials profile to read (overrides APP_PROFILE, default "default")
  --json                    print the result as JSON to stdout, nothing else
  --output string          output format: json, table, or text (default table; --json is shorthand for --output json)
  --query string           JMESPath expression to filter the result before printing
  -h, --help               show this help
```
