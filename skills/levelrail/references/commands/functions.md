## levelrail-cli functions

Subcommands: delete, deploy, dev, init, invocations, invoke, kv, list, runtimes, triggers

```
Usage:
  levelrail-cli functions init <node|python|go> [dir]     write a starter handler
  levelrail-cli functions init <starter> [dir]            write a tested utility: url-shortener, webhook-receiver, form-to-email, scheduled-job-runner, chat-bot
  levelrail-cli functions kv enable|list|get|put|delete <name> ...   the function's key-value store
  levelrail-cli functions deploy <name> --repo <repo URL> [--ref main] [--dir sub/dir] [--port 8080] [--idle 10m] [--env KEY=VALUE ...]
  levelrail-cli functions deploy <name> --image <ref> [--port 8080] [--idle 10m] [--env KEY=VALUE ...]
  levelrail-cli functions deploy <name> ... --domain example.com --path /hello   also serve it at example.com/hello
  levelrail-cli functions list [--window 1h|24h|7d]       state, calls and p95 duration
  levelrail-cli functions invocations <name> [--limit 20]   recent calls with status, duration and cold start
  levelrail-cli functions runtimes
  levelrail-cli functions invoke <name> [--path /] [--method GET] [--data BODY] [--insecure]
  levelrail-cli functions invoke <name> --replay <id>     repeat a recorded call whose input was stored
  levelrail-cli functions dev <dir> [--port 8080] [--env-file .env.local]   run the handler locally in its runtime container
  levelrail-cli functions delete <name>
  levelrail-cli functions settings <name> [--timeout 45s] [--concurrency 20] [--idle 10m]   show or change runtime limits
  levelrail-cli functions versions <name>                 deploy history, newest first
  levelrail-cli functions rollback <name> [--to <deploy id>] [--pin]   return to a version, --pin also locks publishing
  levelrail-cli functions triggers list <name>            webhook, schedules and queue depth of a function
  levelrail-cli functions triggers webhook <name> [--path /] [--rotate] [--disable]   signed webhook trigger
  levelrail-cli functions triggers enqueue <name> [--path /] [--method POST] [--data BODY]   async call with retries
  levelrail-cli functions triggers dead-letters [--function <name>]   calls that ran out of retries
  levelrail-cli functions triggers retry <id> | discard <id>

A function is an app (a handler repo built with Railpack, or an image) that sleeps when idle and starts on the next
request. A request that arrives while it is asleep waits for the cold start
and is then replayed (a 307 redirect, which keeps the method and body), so
callers see one slower response instead of an error page. The container must
serve HTTP on --port. Run "levelrail-cli apps sleep status <name>" for its state.
```

## levelrail-cli functions kv

Subcommands: delete, enable, get, list, put, rotate

```
Usage:
  levelrail-cli functions kv enable <name>                  turn the key-value store on, or issue a new token (rotate)
  levelrail-cli functions kv list <name> [--prefix p] [--limit 100]
  levelrail-cli functions kv get <name> <key>
  levelrail-cli functions kv put <name> <key> <value|-> [--ttl 1h]   "-" reads the value from stdin
  levelrail-cli functions kv delete <name> <key>

The function reads KV_URL and KV_TOKEN from its environment. Rotating the token restarts the function with the new one.
```
