## levelrail-cli domains auth-gate

Subcommands: clear, get, log, revoke, set

```
Usage:
  levelrail-cli domains auth-gate get <app> <domain> [flags]                 show a domain's auth gate
  levelrail-cli domains auth-gate set <app> <domain> --url URL [flags]       check every request with an auth service
  levelrail-cli domains auth-gate set <app> <domain> --provider builtin --allow EMAIL [flags]
                                                                    require this installation's sign-in
  levelrail-cli domains auth-gate clear <app> <domain> [flags]               remove the auth gate
  levelrail-cli domains auth-gate log <app> <domain> [--since 24h]           show the built-in sign-in access log
  levelrail-cli domains auth-gate revoke <app> <domain> [flags]              sign out every visitor of the domain

Sends every request for <domain> to an auth check first (forward auth).
With --provider external (the default) your auth service answers: a 2xx
lets the request through with the --copy-header values set, anything else
(for example a 302 to a login page) goes back to the client unchanged.

With --provider builtin visitors sign in with their account on this
installation and only the users, teams and roles you allow get through;
the app receives X-User, X-Email and X-Name. With no allow rule nobody
gets in. Client-sent copies of the copied headers are always stripped.

Run "levelrail-cli domains auth-gate <subcommand> -h" for a subcommand's own flags.
```

## levelrail-cli domains batch

Subcommands: attach, delete-parked, move, park

```
Usage:
  levelrail-cli domains batch park (--app APP | --static-site SITE) [--env ENV] [--note TEXT] <domain>...
  levelrail-cli domains batch move (--from APP | --from-static-site SITE) (--to APP | --to-static-site SITE) [--from-env ENV] [--to-env ENV] [--confirm] <domain>...
  levelrail-cli domains batch attach (--app APP | --static-site SITE) [--env ENV] [--discard-settings] <domain>...
  levelrail-cli domains batch delete-parked <domain>...
  levelrail-cli domains batch <verb> --file items.json

Runs the same action on several domains in one request. It is not all or
nothing: each domain is checked and applied on its own, a failure does not
stop the others, and the result lists every domain. A move without --confirm
only reports which domains would change owner. --file reads a JSON object
with an "items" array (and optional "confirm" and "discard_settings"), the
same shape the API takes; the verb sets the action.
```

## levelrail-cli domains maintenance

Subcommands: clear, get, preview, set, status

```
Usage:
  levelrail-cli domains maintenance get <app> <domain> [flags]     show a domain's maintenance state
  levelrail-cli domains maintenance set <app> <domain> [flags]     enable maintenance mode (page text, end time, bypass)
  levelrail-cli domains maintenance clear <app> <domain> [flags]   disable maintenance mode
  levelrail-cli domains maintenance <get|set|clear> --app <app>    the same for every domain of the app, all or none
  levelrail-cli domains maintenance status [flags]                 list every domain in maintenance, with how long

While enabled, the embedded Caddy ingress serves a fixed "down for

already be one of <app>'s configured domains (see "levelrail-cli apps get <app>"
or "levelrail-cli domains list").

Turning maintenance on also silences the app's down, uptime and certificate
probe alerts until it ends, and lists open ended maintenance as "ongoing"
on the public status page. "status" shows both effects.

Run "levelrail-cli domains maintenance <subcommand> -h" for a subcommand's own flags.
```

## levelrail-cli domains parked

Subcommands: attach, delete, list, retention

```
Usage:
  levelrail-cli domains park <app> <domain> [--env ENV] [--note TEXT]
  levelrail-cli domains park --static-site SITE <domain> [--note TEXT]
  levelrail-cli domains move <domain> --from APP --to APP [--from-env ENV] [--to-env ENV] [--confirm]
  levelrail-cli domains move <domain> [--from APP | --from-static-site SITE] [--to APP | --to-static-site SITE] [--confirm]
  levelrail-cli domains parked list
  levelrail-cli domains parked attach <domain> --app APP [--env ENV] [--discard-settings]
  levelrail-cli domains parked attach <domain> --static-site SITE
  levelrail-cli domains parked delete <domain>
  levelrail-cli domains parked retention

park takes a domain off an app but keeps it registered, with its DNS records
and certificate untouched, so it can be attached to any app later. move hands
a domain to another app with its per-domain settings; without --confirm it
only runs the collision check. parked delete forgets the registration and
never touches DNS. park keeps the domain's settings (WAF, rate limit, TLS
certificate reference, basic auth, auth gate, maintenance, redirect, error
pages, search settings); parked retention prints the dry run of the
automatic cleanup (setting domains.parked_retention_days, 0 = off); attach restores them unless --discard-settings.
Static sites work the same way through --static-site, --from-static-site and
--to-static-site. A static site has no per-domain settings, so a domain that
moves to or from one, or is attached to one, does not keep them.
Without --env, --from-env and --to-env a command works on the app's default
domain list; with them it works on that environment's own domain set (an
environment ID, name or kind), so an environment domain can be parked, moved
between environments or attached to another app's environment.
```

## levelrail-cli domains standalone

Subcommands: add, list, remove, update

```
Usage:
  levelrail-cli domains standalone list [flags]
  levelrail-cli domains standalone add <domain> --target TARGET [flags]
  levelrail-cli domains standalone update <domain> [flags]
  levelrail-cli domains standalone remove <domain> [flags]

A standalone domain is not linked to any app: the ingress proxies it to
TARGET, which is one of
  3000 or 127.0.0.1:3000          a port on this server
  10.0.0.5:8080, [fd12::5]:80     an address on a private network or the mesh
  https://backend.example.org     an external URL (TLS and Host follow the URL)
  app:NAME[:PORT]                 another app's port (main port by default)
  container:NAME:PORT             a container on this server

Loopback, private and container targets, and this server's own dashboard
or agent port, need --confirm. Metadata and link-local addresses are always
refused. Every per-domain command (basic-auth, waf, headers, go-live, doctor)
works on a standalone domain with _standalone as the app name.
```

```
  levelrail-cli domains tuning set <app> <domain> [--preset NAME] [--compression] [--streaming] [--websocket]
      [--dial-timeout SECONDS] [--response-timeout SECONDS] [--stream-timeout SECONDS] [--close-delay SECONDS]
  levelrail-cli domains tuning clear <app> <domain> [flags]   go back to the ingress defaults

Presets by use case: api (compression, 60s response wait), uploads (300s
response wait), streaming (flush each chunk, 300s response wait) and websocket
(long-lived sockets that survive a config reload). Flags given after a preset
override it. Every number is bounded by the domains.tuning_* runtime settings.
Takes effect on the next ingress reconcile pass.
```

## levelrail-cli domains waf

Subcommands: clear, get, set

```
Usage:
  levelrail-cli domains waf get <app> <domain> [flags]     show a domain's WAF and rate-limit state
  levelrail-cli domains waf set <app> <domain> [flags]     enable/configure the WAF and/or rate limiting
  levelrail-cli domains waf clear <app> <domain> [flags]   turn both off, reverting to unfiltered routing

Opt-in per-domain Web Application Firewall (OWASP Coraza, running the
stock OWASP Core Rule Set) and rate limiting, both enforced by the
embedded Caddy ingress on the next reconcile pass, no separate
container or service. --mode defaults to "detect" (CRS runs and logs
matches but never rejects a request) rather than "block": see
docs/domains-and-ingress.md for why detection-only is the recommended
first-enable default. <domain> must already be one of <app>'s
configured domains (see "levelrail-cli apps get <app>" or "levelrail-cli domains list").

Run "levelrail-cli domains waf <subcommand> -h" for a subcommand's own flags.
```
