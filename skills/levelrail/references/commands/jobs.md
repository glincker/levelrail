## levelrail-cli jobs

Subcommands: create, delete, disable, enable, get, history, list, logs, next, pause, resume, run, update

```
Usage:
  levelrail-cli jobs list <app>
  levelrail-cli jobs get <app> <job>
  levelrail-cli jobs create <app> <name> --schedule CRON [flags] -- <command> [args...]
  levelrail-cli jobs update <app> <job> [flags] [-- <command> [args...]]
  levelrail-cli jobs run <app> <job>
  levelrail-cli jobs run <app> --command "CMD" [--completions N] [--parallelism P] [--backoff-limit B] [--timeout D] [--wait]
  levelrail-cli jobs pause <app> <job>
  levelrail-cli jobs resume <app> <job>
  levelrail-cli jobs next --schedule CRON [--timezone ZONE] [--count N]
  levelrail-cli jobs history <app> [<job>] [--status STATUS] [--limit N]
  levelrail-cli jobs logs <app> <job> [--run RUN_ID]
  levelrail-cli jobs enable <app> <job>
  levelrail-cli jobs disable <app> <job>
  levelrail-cli jobs delete <app> <job>

A job runs a command, or in http mode calls a path on the app, on a cron
schedule (5 fields, or @hourly, @daily, @weekly, @monthly, @yearly). By default each run starts a fresh
container from the app's current image with the app's env, secrets, volumes
and network, and removes it afterwards (--mode exec runs it inside the
running container instead). <job> is the job's name or its ID. <command> is
a real argv, no shell involved; use "sh -c '...'" for a shell pipeline.

One-off runs and scheduled jobs follow console exec access rules: create,
update and run need the root ability on the app and exec enabled for it.

Flags for create and update:
  --schedule CRON        5-field cron expression
  --timezone ZONE        IANA zone the schedule is read in (default UTC)
  --mode MODE            fresh (default), exec or http
  --concurrency POLICY   allow, forbid (skip), replace, queue or queue-one
  --overlap POLICY       allow, skip or queue-one (what a run that is due while
                         the previous one still runs does)
  --alert-on-failure     report failed runs to job_failing alert rules
                         (--alert-on-failure=false turns it off)
  --keep-runs N          keep at most N runs of history (0: server default)
  --keep-days N          keep runs for at most N days (0: server default)
  --http-path PATH       http mode: path on the app to call (wakes it if asleep)
  --http-method METHOD   http mode: GET, POST (default), PUT, PATCH or DELETE
  --http-body TEXT       http mode: request body
  --background           http mode: await the app under the longer
                         background timeout (APP_JOBS_BACKGROUND_TIMEOUT)
  --timeout DURATION     per-attempt timeout, e.g. 10m
  --retries N            retries after a failed attempt
  --retry-backoff DUR    first retry delay, doubled each retry
  --heartbeat-url URL    ping this URL after each successful run (stored encrypted, only the host is shown)
  --heartbeat-fail-url URL
                         ping this URL after a failed run (default: heartbeat-url plus /fail)
  --heartbeat-clear      remove both heartbeat URLs
  --catch-up POLICY      skip (default) or run_once after control plane downtime
  --catch-up-lookback D  how far back run_once still applies
  --cpu CORES            CPU limit for a fresh container, e.g. 0.5
  --memory MB            memory limit in MiB for a fresh container
  --warn-after DURATION  alert when a run exceeds this
  --disabled             create the job disabled

Run "levelrail-cli apps alerts create <app> --kind scheduled_task_failure
--scheduled-task-id ID --restart-count-threshold 1" to be alerted on failure
(also kinds scheduled_task_missed and scheduled_task_running_long).
```
