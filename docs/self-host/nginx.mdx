The Nginx web server on the official Alpine image, serving a persistent web root. It starts with the default welcome page; put your site files in the web root volume through the app's Files.

This page describes the Levelrail template for Nginx (Infrastructure). It deploys the services below as one Docker Compose app on your own server. Project site: https://nginx.org/en/docs/.

Recommended memory: about 64 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `nginx` | `nginx:1.27.2-alpine` | 80 | `nginx_html -&#62; /usr/share/nginx/html` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `nginx` | `TZ` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Stores data in named volumes (`nginx`): nginx_html.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Nginx with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Nginx. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy nginx --name my-nginx
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
