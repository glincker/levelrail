A developer-friendly embedding database for AI applications, served over a simple HTTP API. Open to anyone who can reach it, so reach it from other services in this project at chroma:8000, or attach a domain only behind Basic Auth. Not published on the host.

This page describes the Levelrail template for Chroma (Database Tools). It deploys the services below as one Docker Compose app on your own server. Project site: https://docs.trychroma.com.

Recommended memory: about 512 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `chroma` | `ghcr.io/chroma-core/chroma:1.0.0` | 8000 | `chroma_data -&#62; /data` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `chroma` | `ANONYMIZED_TELEMETRY` | Preset in the template |
| `chroma` | `IS_PERSISTENT` | Preset in the template |
| `chroma` | `PERSIST_DIRECTORY` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Stores data in named volumes (`chroma`): chroma_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Chroma with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Chroma. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy chroma --name my-chroma
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
