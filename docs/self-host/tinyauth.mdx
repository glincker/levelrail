A small login screen and forward-auth server that protects other apps behind your reverse proxy with username and password or OAuth. Runs on SQLite in one container. Users are set with a bcrypt hash in the install form.

This page describes the Levelrail template for Tinyauth (Security). It deploys the services below as one Docker Compose app on your own server. Project site: https://tinyauth.app/docs/getting-started.

Recommended memory: about 64 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `tinyauth` | `ghcr.io/tinyauthapp/tinyauth:v5.2.0` | 3000 | `data -&#62; /data` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `tinyauth` | `TINYAUTH_ANALYTICS_ENABLED` | Preset in the template |
| `tinyauth` | `TINYAUTH_APPURL` | Preset in the template |
| `tinyauth` | `TINYAUTH_AUTH_SECURECOOKIE` | Preset in the template |
| `tinyauth` | `TINYAUTH_AUTH_USERS` | You must provide |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- You must provide one or more secrets before it can deploy (`tinyauth`): TINYAUTH_AUTH_USERS.
- Stores data in named volumes (`tinyauth`): data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

<Warning>This template needs configuration before it can deploy. Open it in the dashboard, set each variable marked "You must provide" in the Compose body, then deploy.</Warning>

## Deploy Tinyauth with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Tinyauth. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates get tinyauth --output json | jq -r .compose > tinyauth.compose.yaml
# edit tinyauth.compose.yaml to set the variables you must provide
levelrail-cli apps deploy-compose my-tinyauth --file tinyauth.compose.yaml
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
