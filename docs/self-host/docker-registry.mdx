A private registry for storing and distributing your own container images.

This page describes the Levelrail template for Docker Registry (Developer Tools). It deploys the services below as one Docker Compose app on your own server. Project site: https://distribution.github.io/distribution/.

Recommended memory: about 256 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `registry` | `registry:3` | 5000 | `registry_data -&#62; /var/lib/registry` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `registry` | `REGISTRY_STORAGE_DELETE_ENABLED` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`registry`): 5000:5000.
- Stores data in named volumes (`registry`): registry_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Docker Registry with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Docker Registry. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy docker-registry --name my-docker-registry
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
