Keeps DNS records pointed at your changing public IP for many providers, with a small web page showing each record's status. The install form carries config.json as an editable file, so you add your providers there.

This page describes the Levelrail template for DDNS Updater (Networking). It deploys the services below as one Docker Compose app on your own server. Project site: https://github.com/qdm12/ddns-updater.

Recommended memory: about 32 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `ddns-updater` | `ghcr.io/qdm12/ddns-updater:v2.10.0` | 8000 | `data -&#62; /updater/data` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `ddns-updater` | `CONFIG_FILEPATH` | Preset in the template |
| `ddns-updater` | `DATADIR` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Stores data in named volumes (`ddns-updater`): data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy DDNS Updater with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select DDNS Updater. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy ddns-updater --name my-ddns-updater
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
