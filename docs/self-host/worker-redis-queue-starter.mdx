A worker process pulling jobs off a Redis-backed queue, the base shape for async job processing.

This page describes the Levelrail template for Background Worker + Redis Queue (Starter Kits). It deploys the services below as one Docker Compose app on your own server. Project site: https://redis.io/docs/latest/develop/data-types/lists/.

Recommended memory: about 192 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `queue` | `redis:7-alpine` | none | `worker_redis_queue_data -&#62; /data` |
| `worker` | `node:22-alpine` | none | none |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `worker` | `NODE_ENV` | Preset in the template |
| `worker` | `QUEUE_URL` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Deploy Background Worker + Redis Queue with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Background Worker + Redis Queue. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy worker-redis-queue-starter --name my-worker-redis-queue-starter
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
