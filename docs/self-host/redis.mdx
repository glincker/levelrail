The Redis in-memory data store on the BSD licensed 7.2 line, with append-only persistence and a generated password. It is not published on the host, so reach it from other services in this project at redis:6379.

This page describes the Levelrail template for Redis (Database Tools). It deploys the services below as one Docker Compose app on your own server. Project site: https://redis.io/docs/.

Recommended memory: about 256 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `redis` | `redis:7.2.7-alpine` | 6379 | `redis_data -&#62; /data` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `redis` | `REDISCLI_AUTH` | Generated at deploy |
| `redis` | `REDIS_PASSWORD` | Generated at deploy |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Passwords and keys are generated at deploy time (`redis`): REDISCLI_AUTH, REDIS_PASSWORD.
- Stores data in named volumes (`redis`): redis_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Redis with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Redis. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy redis --name my-redis
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
