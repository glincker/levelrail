A workflow engine that runs DAGs defined in plain YAML files, with a web UI.

This page describes the Levelrail template for Dagu (Automation). It deploys the services below as one Docker Compose app on your own server. Project site: https://docs.dagu.sh/.

Recommended memory: about 256 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `dagu` | `ghcr.io/dagucloud/dagu:2.25.4` | 8080 | `dagu_data -&#62; /var/lib/dagu` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `dagu` | `DAGU_AUTH_BASIC_PASSWORD` | Generated at deploy |
| `dagu` | `DAGU_AUTH_BASIC_USERNAME` | Preset in the template |
| `dagu` | `DAGU_AUTH_MODE` | Preset in the template |
| `dagu` | `DAGU_HOST` | Preset in the template |
| `dagu` | `DAGU_PORT` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Passwords and keys are generated at deploy time (`dagu`): DAGU_AUTH_BASIC_PASSWORD.
- Stores data in named volumes (`dagu`): dagu_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Dagu with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Dagu. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy dagu --name my-dagu
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
