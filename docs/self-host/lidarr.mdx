Watches your indexers for new albums from artists you follow and automatically grabs and organizes them.

This page describes the Levelrail template for Lidarr (Media). It deploys the services below as one Docker Compose app on your own server. Project site: https://wiki.servarr.com/lidarr.

Recommended memory: about 256 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `lidarr` | `lscr.io/linuxserver/lidarr:2.9.6` | 8686 | `lidarr_config -&#62; /config` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `lidarr` | `PGID` | Preset in the template |
| `lidarr` | `PUID` | Preset in the template |
| `lidarr` | `TZ` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`lidarr`): 8686:8686.
- Stores data in named volumes (`lidarr`): lidarr_config.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Lidarr with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Lidarr. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy lidarr --name my-lidarr
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
