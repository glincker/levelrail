Experimental. Needs APP_EXPERIMENTAL=mail on the control plane: without it this template is hidden and cannot be installed.
Install with the MAIL_FIRST_DOMAIN setting (templates install mail-mox --env MAIL_FIRST_DOMAIN=example.com). MAIL_HOSTNAME (the FQDN other servers connect to) defaults to mail. that domain and MAIL_ADMIN_EMAIL to postmaster@ that domain.
Ports 25, 465, 587 and 993 bind privately by default: set a public bind for each in the app's Network settings and open them in the firewall. Webmail and the account UI are on port 8025 (private, no admin pages). The admin API and metrics are never published; never make them public.
TLS: the first start makes a self-signed certificate (valid for localhost only, made by mox itself) so the server comes up with no manual steps. Replace it before sending real mail: put your certificate and key in the config volume and set MAIL_TLS_CERT_FILE and MAIL_TLS_KEY_FILE (paths under /mox/config, for example certs/cur.pem and certs/cur.key). Existing files at those paths are never overwritten. A changed certificate needs a container restart.
Relay mode: set MAIL_SMARTHOST_HOST (and port, user, password) to send through a provider. Changing it needs a restart.
The admin password is the generated secret SERVICE_PASSWORD_MAILADMIN. Back up the config and data volumes together.
Deliverability depends on reverse DNS, SPF, DKIM and a clean IP; see the mail template guide. Licence: MIT.

This page describes the Levelrail template for Mail server (mox, experimental) (Communication). It deploys the services below as one Docker Compose app on your own server. Project site: https://www.xmox.nl/.

Recommended memory: about 256 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `mox` | `r.xmox.nl/mox:v0.0.17@sha256:8889e7b48fdd5b0b07b51dd11a6d06536334ec442652f2ffb1e1df3a9d45074e` | 8081, 25, 465, 587, 993 | `mail_config -&#62; /mox/config`<br />`mail_data -&#62; /mox/data` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `mox` | `MAIL_ADMIN_EMAIL` | Preset in the template |
| `mox` | `MAIL_ADMIN_PASSWORD` | Generated at deploy |
| `mox` | `MAIL_FIRST_DOMAIN` | You must provide |
| `mox` | `MAIL_HOSTNAME` | Preset in the template |
| `mox` | `MAIL_SMARTHOST_HOST` | Preset in the template |
| `mox` | `MAIL_SMARTHOST_PASSWORD` | Preset in the template |
| `mox` | `MAIL_SMARTHOST_PORT` | Preset in the template |
| `mox` | `MAIL_SMARTHOST_USER` | Preset in the template |
| `mox` | `MAIL_TLS_CERT_FILE` | Preset in the template |
| `mox` | `MAIL_TLS_KEY_FILE` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`mox`): 25:25, 465:465, 587:587, 8025:8081, 993:993.
- You must provide one or more secrets before it can deploy (`mox`): MAIL_FIRST_DOMAIN.
- Passwords and keys are generated at deploy time (`mox`): MAIL_ADMIN_PASSWORD.
- Stores data in named volumes (`mox`): mail_config, mail_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

<Warning>This template needs configuration before it can deploy. Open it in the dashboard, set each variable marked "You must provide" in the Compose body, then deploy.</Warning>

## Deploy Mail server (mox, experimental) with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Mail server (mox, experimental). Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates get mail-mox --output json | jq -r .compose > mail-mox.compose.yaml
# edit mail-mox.compose.yaml to set the variables you must provide
levelrail-cli apps deploy-compose my-mail-mox --file mail-mox.compose.yaml
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
