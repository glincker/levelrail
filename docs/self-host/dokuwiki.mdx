A simple, database-free wiki that stores pages as plain text files, easy to back up.

This page describes the Levelrail template for DokuWiki (Productivity). It deploys the services below as one Docker Compose app on your own server. Project site: https://www.dokuwiki.org/manual.

Recommended memory: about 128 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `dokuwiki` | `lscr.io/linuxserver/dokuwiki:2026-07-14c-ls325` | 80 | `dokuwiki_config -&#62; /config` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `dokuwiki` | `PGID` | Preset in the template |
| `dokuwiki` | `PUID` | Preset in the template |
| `dokuwiki` | `TZ` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`dokuwiki`): 80:80.
- Stores data in named volumes (`dokuwiki`): dokuwiki_config.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy DokuWiki with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select DokuWiki. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy dokuwiki --name my-dokuwiki
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
