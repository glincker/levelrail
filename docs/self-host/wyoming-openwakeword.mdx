Local wake word detection over the Wyoming protocol for Home Assistant voice assistants, preloaded with the ok nabu model.

This page describes the Levelrail template for Wyoming openWakeWord (AI). It deploys the services below as one Docker Compose app on your own server. Project site: https://github.com/rhasspy/wyoming-openwakeword#readme.

Recommended memory: about 256 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `wyoming-openwakeword` | `rhasspy/wyoming-openwakeword:2.1.0` | 10400 | none |

## Environment variables

This template sets no environment variables.

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- No health check, so a deploy is judged by the process starting (`wyoming-openwakeword`).

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Wyoming openWakeWord with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Wyoming openWakeWord. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy wyoming-openwakeword --name my-wyoming-openwakeword
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
