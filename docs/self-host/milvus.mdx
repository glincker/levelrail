A cloud-native vector database built for billion-scale similarity search, run here as a single standalone node.

This page describes the Levelrail template for Milvus (Database Tools). It deploys the services below as one Docker Compose app on your own server. Project site: https://milvus.io/docs.

Recommended memory: about 4096 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `milvus` | `milvusdb/milvus:v3.0.2` | 19530, 9091 | `milvus_data -&#62; /var/lib/milvus` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `milvus` | `COMMON_STORAGETYPE` | Preset in the template |
| `milvus` | `ETCD_DATA_DIR` | Preset in the template |
| `milvus` | `ETCD_USE_EMBED` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`milvus`): 19530:19530, 9091:9091.
- Stores data in named volumes (`milvus`): milvus_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Milvus with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Milvus. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy milvus --name my-milvus
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
