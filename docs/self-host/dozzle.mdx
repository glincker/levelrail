A small web viewer for live container logs on this host. It reads containers and logs through a filtered Docker API proxy, never the raw socket, and has no login, so it ships private with no public domain. Reach it over the private network or an authenticated tunnel and add a domain only behind your own login.

This page describes the Levelrail template for Dozzle (Monitoring). It deploys the services below as one Docker Compose app on your own server. Project site: https://dozzle.dev/guide/getting-started.

Recommended memory: about 64 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `dozzle` | `amir20/dozzle:v11.4.3` | 8080 | `host path -&#62; /var/run/docker.sock` |

## Environment variables

This template sets no environment variables.

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Elevated access**.

What this template needs:

- Mounts the Docker socket, which is equivalent to root on the host (`dozzle`): /var/run/docker.sock.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Dozzle with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Dozzle. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy dozzle --name my-dozzle
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
