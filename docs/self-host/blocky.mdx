DNS proxy and ad blocker with caching and conditional forwarding. The install form carries config.yml as an editable file, so it starts with a small denylist and public upstream resolvers.

This page describes the Levelrail template for Blocky (Networking). It deploys the services below as one Docker Compose app on your own server. Project site: https://0xerr0r.github.io/blocky/.

Recommended memory: about 64 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `blocky` | `ghcr.io/0xerr0r/blocky:v0.36.0` | 4000, 5353 | none |

## Environment variables

This template sets no environment variables.

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- No health check, so a deploy is judged by the process starting (`blocky`).

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Blocky with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Blocky. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy blocky --name my-blocky
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
