Fast, lightweight schema less search index server that stores identifiers instead of documents. The install form carries config.cfg as an editable file and a generated channel password.

This page describes the Levelrail template for Sonic (Database Tools). It deploys the services below as one Docker Compose app on your own server. Project site: https://github.com/valeriansaliou/sonic#how-to-use-it.

Recommended memory: about 128 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `sonic` | `valeriansaliou/sonic:v1.10.2` | 1491 | `store -&#62; /var/lib/sonic/store` |

## Environment variables

This template sets no environment variables.

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- No health check, so a deploy is judged by the process starting (`sonic`).
- Stores data in named volumes (`sonic`): store.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Sonic with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Sonic. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy sonic --name my-sonic
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
