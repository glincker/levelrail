The classic self-hosted file sync and share platform, with MariaDB and Redis for metadata and locking.

This page describes the Levelrail template for ownCloud (Storage). It deploys the services below as one Docker Compose app on your own server. Project site: https://doc.owncloud.com/server/.

Recommended memory: about 1024 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `mariadb` | `mariadb:11.2` | none | `db -&#62; /var/lib/mysql` |
| `owncloud` | `owncloud/server:10.15` | 8080 | `files -&#62; /mnt/data` |
| `redis` | `redis:7-alpine` | none | `redis -&#62; /data` |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Passwords and keys are generated at deploy time (`mariadb`, `owncloud`): MYSQL_PASSWORD, MYSQL_ROOT_PASSWORD, OWNCLOUD_ADMIN_PASSWORD, OWNCLOUD_DB_PASSWORD.
- Stores data in named volumes (`mariadb`, `owncloud`, `redis`): db, files, redis.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy ownCloud with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select ownCloud. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy owncloud --name my-owncloud
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
