Disposable mail server that catches mail for any address and shows it in a web inbox, for testing apps without sending real email.

This page describes the Levelrail template for Inbucket (Developer Tools). It deploys the services below as one Docker Compose app on your own server. Project site: https://www.inbucket.org/.

Recommended memory: about 64 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `inbucket` | `inbucket/inbucket:3.2.0` | 9000, 2500 | `data -&#62; /storage` |

## Environment variables

This template sets no environment variables.

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- No health check, so a deploy is judged by the process starting (`inbucket`).
- Stores data in named volumes (`inbucket`): data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Inbucket with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Inbucket. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy inbucket --name my-inbucket
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
