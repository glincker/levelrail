One Nginx entrypoint routing to two independent backend services, demonstrating depends_on across three services.

This page describes the Levelrail template for Nginx Reverse Proxy (Multi-Backend) (Starter Kits). It deploys the services below as one Docker Compose app on your own server. Project site: https://nginx.org/en/docs/http/ngx_http_proxy_module.html.

Recommended memory: about 192 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `orders` | `node:22-alpine` | none | none |
| `payments` | `node:22-alpine` | none | none |
| `proxy` | `nginx:1.27-alpine` | 80 | none |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `orders` | `NODE_ENV` | Preset in the template |
| `payments` | `NODE_ENV` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`proxy`): 8080:80.
- No health check, so a deploy is judged by the process starting (`orders`, `payments`).

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Nginx Reverse Proxy (Multi-Backend) with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Nginx Reverse Proxy (Multi-Backend). Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy nginx-multi-backend-starter --name my-nginx-multi-backend-starter
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
