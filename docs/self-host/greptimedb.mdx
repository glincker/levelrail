A time series database for metrics, logs and traces with SQL, PromQL and OpenTelemetry ingest. This runs a single standalone node with no login on the HTTP port.

This page describes the Levelrail template for GreptimeDB (Databases). It deploys the services below as one Docker Compose app on your own server. Project site: https://docs.greptime.com/getting-started/installation/greptimedb-standalone/.

Recommended memory: about 512 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `greptimedb` | `greptime/greptimedb:v1.3.0` | 4000 | `data -&#62; /greptimedb_data` |

## Environment variables

This template sets no environment variables.

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Stores data in named volumes (`greptimedb`): data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy GreptimeDB with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select GreptimeDB. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy greptimedb --name my-greptimedb
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.

All templates are listed in the [self-host gallery](/self-host).
