Harness Open Source, a Git host with code review, pipelines and an artifact registry in one binary. Apache-2.0 licensed. Uses an embedded SQLite database on the data volume. The first user to register becomes the admin, then turn off sign-ups. Pipelines that run containers need Docker access, which this template does not grant.

This page describes the Levelrail template for Gitness (Developer Tools). It deploys the services below as one Docker Compose app on your own server. Project site: https://docs.harness.io/open-source.

Recommended memory: about 384 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `gitness` | `harness/harness:3.3.0` | 3000 | `data -&#62; /data` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `gitness` | `GITNESS_URL_BASE` | Preset in the template |
| `gitness` | `GITNESS_USER_SIGNUP_ENABLED` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Stores data in named volumes (`gitness`): data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Gitness with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Gitness. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy gitness --name my-gitness
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
