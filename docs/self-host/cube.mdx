A semantic layer that serves one set of metric definitions to dashboards, notebooks and AI tools over SQL and REST. Apache-2.0 licensed. This runs in development mode with the playground enabled, so keep it private.

This page describes the Levelrail template for Cube (Analytics). It deploys the services below as one Docker Compose app on your own server. Project site: https://github.com/cube-js/cube.

Recommended memory: about 1024 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `cube` | `cubejs/cube:v1.8.21` | 4000 | `conf -&#62; /cube/conf` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `cube` | `CUBEJS_API_SECRET` | Generated at deploy |
| `cube` | `CUBEJS_DEV_MODE` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Passwords and keys are generated at deploy time (`cube`): CUBEJS_API_SECRET.
- Stores data in named volumes (`cube`): conf.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Cube with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Cube. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy cube --name my-cube
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
