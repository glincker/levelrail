A fast, resource-frugal time-series database that speaks the Prometheus query and remote-write APIs. Has no authentication, so point Prometheus-style senders at victoriametrics:8428 from other services in this project, or attach a domain only behind Basic Auth. Not published on the host.

This page describes the Levelrail template for VictoriaMetrics (Monitoring). It deploys the services below as one Docker Compose app on your own server. Project site: https://docs.victoriametrics.com.

Recommended memory: about 512 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `victoriametrics` | `victoriametrics/victoria-metrics:v1.152.0` | 8428 | `victoriametrics_data -&#62; /storage` |

## Environment variables

This template sets no environment variables.

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Stores data in named volumes (`victoriametrics`): victoriametrics_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy VictoriaMetrics with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select VictoriaMetrics. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy victoriametrics --name my-victoriametrics
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
