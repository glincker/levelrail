A self-hosted file management and sharing system with multiple storage backends.

This page describes the Levelrail template for Cloudreve (Storage). It deploys the services below as one Docker Compose app on your own server. Project site: https://docs.cloudreve.org/.

Recommended memory: about 512 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `cloudreve` | `cloudreve/cloudreve:4.10.1` | 5212 | `cloudreve_data -&#62; /cloudreve/data` |
| `postgres` | `postgres:16-alpine` | none | `postgres_data -&#62; /var/lib/postgresql/data` |
| `redis` | `redis:7-alpine` | none | `redis_data -&#62; /data` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `cloudreve` | `CR_CONF_Database.Host` | Preset in the template |
| `cloudreve` | `CR_CONF_Database.Name` | Preset in the template |
| `cloudreve` | `CR_CONF_Database.Password` | Generated at deploy |
| `cloudreve` | `CR_CONF_Database.Port` | Preset in the template |
| `cloudreve` | `CR_CONF_Database.Type` | Preset in the template |
| `cloudreve` | `CR_CONF_Database.User` | Preset in the template |
| `cloudreve` | `CR_CONF_Redis.Password` | Generated at deploy |
| `cloudreve` | `CR_CONF_Redis.Server` | Preset in the template |
| `postgres` | `POSTGRES_DB` | Preset in the template |
| `postgres` | `POSTGRES_PASSWORD` | Generated at deploy |
| `postgres` | `POSTGRES_USER` | Preset in the template |
| `redis` | `REDIS_PASSWORD` | Generated at deploy |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`cloudreve`): 5212:5212.
- Passwords and keys are generated at deploy time (`cloudreve`, `postgres`, `redis`): CR_CONF_Database.Password, CR_CONF_Redis.Password, POSTGRES_PASSWORD, REDIS_PASSWORD.
- Stores data in named volumes (`cloudreve`, `postgres`, `redis`): cloudreve_data, postgres_data, redis_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Cloudreve with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Cloudreve. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy cloudreve --name my-cloudreve
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
