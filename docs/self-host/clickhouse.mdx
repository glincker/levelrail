A columnar database built for fast analytical queries over large datasets.

This page describes the Levelrail template for ClickHouse (Database Tools). It deploys the services below as one Docker Compose app on your own server. Project site: https://hub.docker.com/r/clickhouse/clickhouse-server.

Recommended memory: about 1024 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `clickhouse` | `clickhouse/clickhouse-server:26.3-alpine` | 8123 | `clickhouse_data -&#62; /var/lib/clickhouse` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `clickhouse` | `CLICKHOUSE_PASSWORD` | Generated at deploy |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`clickhouse`): 8123:8123.
- Passwords and keys are generated at deploy time (`clickhouse`): CLICKHOUSE_PASSWORD.
- Stores data in named volumes (`clickhouse`): clickhouse_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy ClickHouse with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select ClickHouse. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy clickhouse --name my-clickhouse
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
