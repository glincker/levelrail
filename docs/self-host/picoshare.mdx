Minimalist file sharing service for sending large files by link with an optional expiry. A generated shared secret protects the upload page.

This page describes the Levelrail template for PicoShare (Storage). It deploys the services below as one Docker Compose app on your own server. Project site: https://github.com/mtlynch/picoshare#readme.

Recommended memory: about 64 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `picoshare` | `mtlynch/picoshare:v1.5.4` | 4001 | `data -&#62; /data` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `picoshare` | `PORT` | Preset in the template |
| `picoshare` | `PS_SHARED_SECRET` | Generated at deploy |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Passwords and keys are generated at deploy time (`picoshare`): PS_SHARED_SECRET.
- No health check, so a deploy is judged by the process starting (`picoshare`).
- Stores data in named volumes (`picoshare`): data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy PicoShare with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select PicoShare. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy picoshare --name my-picoshare
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
