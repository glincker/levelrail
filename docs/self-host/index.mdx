- [Mail server (mox, experimental)](/self-host/mail-mox): Experimental. Needs APP_EXPERIMENTAL=mail on the control plane: without it this template is hidden and cannot be installed.
Install with the MAIL_FIRST_DOMAIN setting (templates install mail-mox --env MAIL_FIRST_DOMAIN=example.com). MAIL_HOSTNAME (the FQDN other servers connect to) defaults to mail. that domain and MAIL_ADMIN_EMAIL to postmaster@ that domain.
Ports 25, 465, 587 and 993 are published on the host with a private bind by default. After install, open them with the CLI command mail ports open --confirm (or Open mail ports on the Mail page): that makes only those four ports public and allows them in the host firewall, then set up DNS. Webmail and the account UI are on port 8025 (private, no admin pages). The admin API and metrics are never published; never make them public.
TLS: the first start makes a self-signed certificate (valid for localhost only, made by mox itself) so the server comes up with no manual steps. Replace it before sending real mail: put your certificate and key in the config volume and set MAIL_TLS_CERT_FILE and MAIL_TLS_KEY_FILE (paths under /mox/config, for example certs/cur.pem and certs/cur.key). Existing files at those paths are never overwritten. A changed certificate needs a container restart.
Relay mode: set MAIL_SMARTHOST_HOST (and port, user, password) to send through a provider. Changing it needs a restart.
The admin password is the generated secret SERVICE_PASSWORD_MAILADMIN. Back up the config and data volumes together.
Deliverability depends on reverse DNS, SPF, DKIM and a clean IP; see the mail template guide. Licence: MIT.

- [Chibisafe](/self-host/chibisafe): A file vault for uploading and sharing files from the cloud.
- [Cloudreve](/self-host/cloudreve): A self-hosted file management and sharing system with multiple storage backends.
- [copyparty](/self-host/copyparty): A portable file server with resumable uploads, a media player, and search, in a single small image.
- [Dufs](/self-host/dufs): A tiny file server with uploads, downloads, search and WebDAV over one login. Apache-2.0 licensed. The admin password is generated for you.
- [Duplicati](/self-host/duplicati): Scheduled, encrypted backups of your files to local storage, network shares, or cloud storage.
- [File Browser](/self-host/filebrowser): A simple web UI for browsing, uploading, and sharing files from your own storage.
- [FileBrowser Quantum](/self-host/filebrowser-quantum): A web file manager with a fast index, search, sharing links and per-user access. Apache-2.0 fork of FileBrowser. Runs in one container; the admin password is generated and shown in the service environment settings.
- [Kopia](/self-host/kopia): Fast, incremental, encrypted backups to a repository, driven from a web UI instead of a cron script.
- [MinIO](/self-host/minio): S3-compatible object storage you run yourself, with a built-in web console.
- [ownCloud](/self-host/owncloud): The classic self-hosted file sync and share platform, with MariaDB and Redis for metadata and locking.
- [PicoShare](/self-host/picoshare): Minimalist file sharing service for sending large files by link with an optional expiry. A generated shared secret protects the upload page.
- [Pingvin Share](/self-host/pingvin-share): A self-hosted, ad-free alternative to WeTransfer for sending files with expiring links.
- [RustFS](/self-host/rustfs): An S3-compatible object storage server written in Rust, with a web console. One container serves the S3 API on port 9000 and the console on port 9001. Access and secret keys are generated at install time.
- [Seafile](/self-host/seafile): Self-hosted file sync and share with real file-level versioning and client-side encryption options.
- [SeaweedFS](/self-host/seaweedfs): A distributed file and object store with an S3 gateway, built for billions of small files.
- [SFTPGo](/self-host/sftpgo): An SFTP, FTP/S, and WebDAV server with a web admin UI and per-user storage backends.
- [Syncthing](/self-host/syncthing): Continuous, peer-to-peer file synchronization between your own devices, no cloud in between.
- [WebDAV Server](/self-host/webdav): Small standalone WebDAV server with per user permissions. The install form carries config.yml as an editable file and a generated admin password.
- [Zipline](/self-host/zipline): A self-hosted file and screenshot host with a share-first upload flow and its own URL shortener.
