A spreadsheet-style visual database backed by real PostgreSQL, an Airtable alternative.

This page describes the Levelrail template for Teable (Productivity). It deploys the services below as one Docker Compose app on your own server. Project site: https://help.teable.io/.

Recommended memory: about 1024 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `teable` | `ghcr.io/teableio/teable:latest` | 3000 | `teable_data -&#62; /app/.assets` |
| `teable-cache` | `redis:7.2.4` | none | `teable_cache_data -&#62; /data` |
| `teable-db` | `postgres:15.4` | none | `teable_db_data -&#62; /var/lib/postgresql/data` |
| `teable-db-migrate` | `ghcr.io/teableio/teable-db-migrate:latest` | none | none |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `teable` | `BACKEND_CACHE_PROVIDER` | Preset in the template |
| `teable` | `BACKEND_CACHE_REDIS_URI` | Preset in the template |
| `teable` | `PORT` | Preset in the template |
| `teable` | `PRISMA_DATABASE_URL` | Generated at deploy |
| `teable` | `PUBLIC_ORIGIN` | Preset in the template |
| `teable` | `SECRET_KEY` | Generated at deploy |
| `teable-db` | `POSTGRES_DB` | Preset in the template |
| `teable-db` | `POSTGRES_PASSWORD` | Generated at deploy |
| `teable-db` | `POSTGRES_USER` | Preset in the template |
| `teable-db-migrate` | `PRISMA_DATABASE_URL` | Generated at deploy |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Review before deploying**.

What this template needs:

- Image is not pinned to a version tag, so a redeploy can pull different code (`teable`, `teable-db-migrate`): ghcr.io/teableio/teable-db-migrate:latest, ghcr.io/teableio/teable:latest.
- Publishes ports directly on the host (`teable`): 3000:3000.
- Passwords and keys are generated at deploy time (`teable`, `teable-db`, `teable-db-migrate`): POSTGRES_PASSWORD, PRISMA_DATABASE_URL, PRISMA_DATABASE_URL, SECRET_KEY.
- No health check, so a deploy is judged by the process starting (`teable-db-migrate`).
- Stores data in named volumes (`teable`, `teable-cache`, `teable-db`): teable_cache_data, teable_data, teable_db_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Teable with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Teable. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy teable --name my-teable
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
