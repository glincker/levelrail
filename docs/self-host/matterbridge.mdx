Bridges chat between platforms. The install form carries matterbridge.toml as an editable file with a local API gateway, so you add your own accounts there.

This page describes the Levelrail template for Matterbridge (Communication). It deploys the services below as one Docker Compose app on your own server. Project site: https://github.com/42wim/matterbridge/wiki.

Recommended memory: about 64 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `matterbridge` | `42wim/matterbridge:1.26.0` | 4242 | none |

## Environment variables

This template sets no environment variables.

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- No health check, so a deploy is judged by the process starting (`matterbridge`).

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Matterbridge with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Matterbridge. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy matterbridge --name my-matterbridge
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
