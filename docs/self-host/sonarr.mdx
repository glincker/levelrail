Watches your favorite indexers for new TV episodes and automatically grabs, sorts, and renames them.

This page describes the Levelrail template for Sonarr (Media). It deploys the services below as one Docker Compose app on your own server. Project site: https://wiki.servarr.com/sonarr.

Recommended memory: about 256 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `sonarr` | `lscr.io/linuxserver/sonarr:4.0.12` | 8989 | `sonarr_config -&#62; /config` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `sonarr` | `PGID` | Preset in the template |
| `sonarr` | `PUID` | Preset in the template |
| `sonarr` | `TZ` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`sonarr`): 8989:8989.
- Stores data in named volumes (`sonarr`): sonarr_config.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Sonarr with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Sonarr. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy sonarr --name my-sonarr
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
