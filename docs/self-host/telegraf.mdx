Plugin driven agent that collects metrics and exposes them for Prometheus. The install form carries telegraf.conf as an editable file, so it starts with CPU, memory and disk inputs already wired.

This page describes the Levelrail template for Telegraf (Monitoring). It deploys the services below as one Docker Compose app on your own server. Project site: https://docs.influxdata.com/telegraf/.

Recommended memory: about 128 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `telegraf` | `telegraf:1.40.3` | 9273 | none |

## Environment variables

This template sets no environment variables.

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- No health check, so a deploy is judged by the process starting (`telegraf`).

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Telegraf with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Telegraf. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy telegraf --name my-telegraf
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
