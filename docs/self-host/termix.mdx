A web-based SSH, RDP, and VNC terminal manager for organizing and connecting to every server from one dashboard.

This page describes the Levelrail template for Termix (Developer Tools). It deploys the services below as one Docker Compose app on your own server. Project site: https://github.com/LukeGus/Termix.

Recommended memory: about 256 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `guacd` | `guacamole/guacd:1.6.0` | none | none |
| `termix` | `ghcr.io/lukegus/termix:2.6.1` | 8080 | `termix_data -&#62; /app/data` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `termix` | `GUACD_HOST` | Preset in the template |
| `termix` | `GUACD_RECORDING_PATH` | Preset in the template |
| `termix` | `PORT` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`termix`): 8080:8080.
- No health check, so a deploy is judged by the process starting (`guacd`).
- Stores data in named volumes (`termix`): termix_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Termix with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Termix. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy termix --name my-termix
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
