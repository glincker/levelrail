A widely used open-source message broker supporting AMQP, MQTT, and STOMP.

This page describes the Levelrail template for RabbitMQ (Infrastructure). It deploys the services below as one Docker Compose app on your own server. Project site: https://www.rabbitmq.com/documentation.html.

Recommended memory: about 512 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `rabbitmq` | `rabbitmq:3.13-management-alpine` | 15672 | `rabbitmq_data -&#62; /var/lib/rabbitmq` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `rabbitmq` | `RABBITMQ_DEFAULT_PASS` | Generated at deploy |
| `rabbitmq` | `RABBITMQ_DEFAULT_USER` | Generated at deploy |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`rabbitmq`): 15672:15672.
- Passwords and keys are generated at deploy time (`rabbitmq`): RABBITMQ_DEFAULT_PASS, RABBITMQ_DEFAULT_USER.
- Stores data in named volumes (`rabbitmq`): rabbitmq_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy RabbitMQ with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select RabbitMQ. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy rabbitmq --name my-rabbitmq
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
