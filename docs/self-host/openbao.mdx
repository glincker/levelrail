OpenBao, the open source secrets manager forked from Vault, with integrated Raft storage. It is reachable only from services in this project at openbao:8200 over plain HTTP and is not published on the host.

This page describes the Levelrail template for OpenBao (Security). It deploys the services below as one Docker Compose app on your own server. Project site: https://openbao.org/docs/.

Recommended memory: about 256 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `openbao` | `ghcr.io/openbao/openbao:2.7.2` | 8200 | `openbao_data -&#62; /openbao/file` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `openbao` | `BAO_ADDR` | Preset in the template |
| `openbao` | `BAO_LOCAL_CONFIG` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Stores data in named volumes (`openbao`): openbao_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy OpenBao with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select OpenBao. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy openbao --name my-openbao
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
