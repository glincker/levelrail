A lightweight MQTT broker for connecting IoT devices, sensors, and home automation hubs.

This page describes the Levelrail template for Eclipse Mosquitto (IoT). It deploys the services below as one Docker Compose app on your own server. Project site: https://mosquitto.org/documentation/.

Recommended memory: about 128 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `mosquitto` | `eclipse-mosquitto:2.0.20` | 1883 | `mosquitto_data -&#62; /mosquitto/data` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `mosquitto` | `MQTT_PASSWORD` | Generated at deploy |
| `mosquitto` | `MQTT_USER` | Generated at deploy |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`mosquitto`): 1883:1883.
- Passwords and keys are generated at deploy time (`mosquitto`): MQTT_PASSWORD, MQTT_USER.
- Stores data in named volumes (`mosquitto`): mosquitto_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Eclipse Mosquitto with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Eclipse Mosquitto. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy mosquitto --name my-mosquitto
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
