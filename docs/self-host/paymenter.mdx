Open-source billing and client management for hosting providers, with invoices, subscriptions and provisioning extensions.

This page describes the Levelrail template for Paymenter (Finance). It deploys the services below as one Docker Compose app on your own server. Project site: https://paymenter.org/docs/guides/docker.

Recommended memory: about 768 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `mariadb` | `mariadb:11.8` | none | `mariadb -&#62; /var/lib/mysql` |
| `paymenter` | `ghcr.io/paymenter/paymenter:v1.4.5` | 80 | `logs -&#62; /app/storage/logs`<br />`extensions -&#62; /app/extensions`<br />`themes -&#62; /app/themes`<br />`storage -&#62; /app/storage/app` |
| `redis` | `redis:7-alpine` | none | none |

## Security and requirements

Level: **Standard**.

What this template needs:

- Passwords and keys are generated at deploy time (`mariadb`, `paymenter`, `redis`): APP_KEY, DB_PASSWORD, REDIS_PASSWORD, MYSQL_PASSWORD, MYSQL_ROOT_PASSWORD, REDIS_PASSWORD.
- Stores data in named volumes (`mariadb`, `paymenter`): extensions, logs, mariadb, storage, themes.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Paymenter with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Paymenter. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy paymenter --name my-paymenter
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
