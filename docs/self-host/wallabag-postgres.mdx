A read it later app that saves web articles in a clean, distraction free format, with its data kept in a bundled Postgres database instead of SQLite. The default login is wallabag with the password wallabag, change it first.

This page describes the Levelrail template for Wallabag with Postgres (Productivity). It deploys the services below as one Docker Compose app on your own server. Project site: https://doc.wallabag.org/.

Recommended memory: about 512 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `db` | `postgres:17.11-alpine` | none | `pgdata -&#62; /var/lib/postgresql/data` |
| `wallabag` | `wallabag/wallabag:2.6.15` | 80 | `wallabag_images -&#62; /var/www/wallabag/web/assets/images` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `db` | `POSTGRES_DB` | Preset in the template |
| `db` | `POSTGRES_PASSWORD` | Generated at deploy |
| `db` | `POSTGRES_USER` | Preset in the template |
| `wallabag` | `SYMFONY__ENV__DATABASE_CHARSET` | Preset in the template |
| `wallabag` | `SYMFONY__ENV__DATABASE_DRIVER` | Preset in the template |
| `wallabag` | `SYMFONY__ENV__DATABASE_HOST` | Preset in the template |
| `wallabag` | `SYMFONY__ENV__DATABASE_NAME` | Preset in the template |
| `wallabag` | `SYMFONY__ENV__DATABASE_PASSWORD` | Generated at deploy |
| `wallabag` | `SYMFONY__ENV__DATABASE_PORT` | Preset in the template |
| `wallabag` | `SYMFONY__ENV__DATABASE_USER` | Preset in the template |
| `wallabag` | `SYMFONY__ENV__DOMAIN_NAME` | Preset in the template |
| `wallabag` | `SYMFONY__ENV__FOSUSER_REGISTRATION` | Preset in the template |
| `wallabag` | `SYMFONY__ENV__SECRET` | Generated at deploy |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Passwords and keys are generated at deploy time (`db`, `wallabag`): POSTGRES_PASSWORD, SYMFONY__ENV__DATABASE_PASSWORD, SYMFONY__ENV__SECRET.
- Stores data in named volumes (`db`, `wallabag`): pgdata, wallabag_images.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Wallabag with Postgres with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Wallabag with Postgres. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy wallabag-postgres --name my-wallabag-postgres
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
