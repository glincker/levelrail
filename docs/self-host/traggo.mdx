Self-hosted time tracking with tags instead of projects, a timeline and dashboards. Runs a single container with data on a volume.

This page describes the Levelrail template for Traggo (Productivity). It deploys the services below as one Docker Compose app on your own server. Project site: https://traggo.net/.

Recommended memory: about 64 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `traggo` | `traggo/server:0.8.3` | 3030 | `data -&#62; /opt/traggo/data` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `traggo` | `TRAGGO_DEFAULT_USER_NAME` | Preset in the template |
| `traggo` | `TRAGGO_DEFAULT_USER_PASS` | Generated at deploy |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Passwords and keys are generated at deploy time (`traggo`): TRAGGO_DEFAULT_USER_PASS.
- No health check, so a deploy is judged by the process starting (`traggo`).
- Stores data in named volumes (`traggo`): data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Traggo with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Traggo. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy traggo --name my-traggo
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
