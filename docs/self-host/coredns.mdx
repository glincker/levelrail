Plugin based DNS server on the official image. The install form carries the Corefile as an editable file, so it starts as a caching forwarder with health and readiness endpoints.

This page describes the Levelrail template for CoreDNS (Networking). It deploys the services below as one Docker Compose app on your own server. Project site: https://coredns.io/manual/toc/.

Recommended memory: about 64 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `coredns` | `coredns/coredns:1.15.0` | 8080, 1053 | none |

## Environment variables

This template sets no environment variables.

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- No health check, so a deploy is judged by the process starting (`coredns`).

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy CoreDNS with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select CoreDNS. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy coredns --name my-coredns
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
