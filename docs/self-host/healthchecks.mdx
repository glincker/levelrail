Cron job and scheduled task monitoring: get alerted the moment a periodic job stops checking in.

This page describes the Levelrail template for Healthchecks (Monitoring). It deploys the services below as one Docker Compose app on your own server. Project site: https://healthchecks.io/docs/self_hosted/.

Recommended memory: about 256 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `db` | `postgres:16-alpine` | none | `healthchecks_db_data -&#62; /var/lib/postgresql/data` |
| `healthchecks` | `healthchecks/healthchecks:v4.2` | 8000 | none |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `db` | `POSTGRES_DB` | Preset in the template |
| `db` | `POSTGRES_PASSWORD` | Generated at deploy |
| `db` | `POSTGRES_USER` | Preset in the template |
| `healthchecks` | `ALLOWED_HOSTS` | Preset in the template |
| `healthchecks` | `DB` | Preset in the template |
| `healthchecks` | `DB_HOST` | Preset in the template |
| `healthchecks` | `DB_NAME` | Preset in the template |
| `healthchecks` | `DB_PASSWORD` | Generated at deploy |
| `healthchecks` | `DB_USER` | Preset in the template |
| `healthchecks` | `SECRET_KEY` | Generated at deploy |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`healthchecks`): 8000:8000.
- Passwords and keys are generated at deploy time (`db`, `healthchecks`): DB_PASSWORD, SECRET_KEY, POSTGRES_PASSWORD.
- No health check, so a deploy is judged by the process starting (`db`).
- Stores data in named volumes (`db`): healthchecks_db_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Healthchecks with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Healthchecks. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy healthchecks --name my-healthchecks
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
