Multi user server that manages and proxies notebook servers. The install form carries jupyterhub_config.py as an editable file with a generated shared password, so it starts with a working login.

This page describes the Levelrail template for JupyterHub (Developer Tools). It deploys the services below as one Docker Compose app on your own server. Project site: https://jupyterhub.readthedocs.io/.

Recommended memory: about 256 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `jupyterhub` | `quay.io/jupyterhub/jupyterhub:5.4.0` | 8000 | `data -&#62; /srv/jupyterhub/state` |

## Environment variables

This template sets no environment variables.

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- No health check, so a deploy is judged by the process starting (`jupyterhub`).
- Stores data in named volumes (`jupyterhub`): data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy JupyterHub with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select JupyterHub. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy jupyterhub --name my-jupyterhub
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
