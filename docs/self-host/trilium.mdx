A hierarchical, self-hosted note-taking application built for large personal knowledge bases.

This page describes the Levelrail template for TriliumNext Notes (Productivity). It deploys the services below as one Docker Compose app on your own server. Project site: https://triliumnext.github.io/Docs/.

Recommended memory: about 256 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `trilium` | `ghcr.io/triliumnext/trilium:stable` | 8080 | `trilium_data -&#62; /home/node/trilium-data` |

## Environment variables

This template sets no environment variables.

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`trilium`): 8080:8080.
- Stores data in named volumes (`trilium`): trilium_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy TriliumNext Notes with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select TriliumNext Notes. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy trilium --name my-trilium
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
