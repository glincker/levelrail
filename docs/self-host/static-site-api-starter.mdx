A static frontend and a separate API service deployed together, the split most SPAs actually run.

This page describes the Levelrail template for Static Site + API Backend (Starter Kits). It deploys the services below as one Docker Compose app on your own server. Project site: https://nginx.org/en/docs/.

Recommended memory: about 128 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `api` | `node:22-alpine` | 4000 | none |
| `static` | `nginx:1.27-alpine` | 80 | none |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `api` | `NODE_ENV` | Preset in the template |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`api`, `static`): 4000:4000, 8080:80.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Static Site + API Backend with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Static Site + API Backend. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy static-site-api-starter --name my-static-site-api-starter
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
