A programmable, Markdown-based notes app you can extend with your own scripts and queries.

This page describes the Levelrail template for SilverBullet (Productivity). It deploys the services below as one Docker Compose app on your own server. Project site: https://silverbullet.md.

Recommended memory: about 256 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `silverbullet` | `ghcr.io/silverbulletmd/silverbullet:2.11.1` | 3000 | `silverbullet_space -&#62; /space` |

## Environment variables

| Service | Variable | Value |
| --- | --- | --- |
| `silverbullet` | `SB_USER` | Generated at deploy |

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`silverbullet`): 3000:3000.
- Passwords and keys are generated at deploy time (`silverbullet`): SB_USER.
- Stores data in named volumes (`silverbullet`): silverbullet_space.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Secrets are generated, stored encrypted and masked in logs and the UI.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy SilverBullet with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select SilverBullet. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy silverbullet --name my-silverbullet
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
