A Prometheus Pushgateway that holds metrics pushed by short-lived batch jobs so a Prometheus server can scrape them. Pushed groups are kept on a persistent volume.

This page describes the Levelrail template for Pushgateway (Monitoring). It deploys the services below as one Docker Compose app on your own server. Project site: https://prometheus.io/docs/practices/pushing/.

Recommended memory: about 64 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `pushgateway` | `prom/pushgateway:v1.11.4` | 9091 | `pushgateway_data -&#62; /data` |

## Environment variables

This template sets no environment variables.

Passwords and keys marked as generated are created for you when the app is deployed and stored as secrets. Values are not shown here.

## Security and requirements

Level: **Standard**.

What this template needs:

- Stores data in named volumes (`pushgateway`): pushgateway_data.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Pushgateway with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Pushgateway. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy pushgateway --name my-pushgateway
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
