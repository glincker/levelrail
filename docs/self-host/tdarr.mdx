Automated media transcoding, health checks, and library-wide format standardization.

This page describes the Levelrail template for Tdarr (Media). It deploys the services below as one Docker Compose app on your own server. Project site: https://docs.tdarr.io.

Recommended memory: about 1024 MiB.

## Services, ports and volumes

| Service | Image | Container ports | Volumes |
| --- | --- | --- | --- |
| `tdarr` | `ghcr.io/haveagitgat/tdarr:2.86.01` | 8265 | `tdarr_server -&#62; /app/server`<br />`tdarr_configs -&#62; /app/configs`<br />`tdarr_logs -&#62; /app/logs`<br />`tdarr_media -&#62; /media`<br />`tdarr_transcode_cache -&#62; /temp` |

## Security and requirements

Level: **Standard**.

What this template needs:

- Publishes ports directly on the host (`tdarr`): 8265:8265.
- Stores data in named volumes (`tdarr`): tdarr_configs, tdarr_logs, tdarr_media, tdarr_server, tdarr_transcode_cache.

What Levelrail adds around it:

- Automatic HTTPS and an ingress shield in front of every domain.
- Named volumes can be backed up and restored.
- Deploys are gated on the health check before traffic switches.
- One-step rollback to the previous revision.
- Exposure report shows what is reachable from outside.
- Host firewall rules managed for published ports.

## Deploy Tdarr with Levelrail

In the dashboard, open **Apps**, choose **New app**, then **Browse templates**, and select Tdarr. Review the Compose body and deploy.

With the CLI:

```bash
levelrail-cli templates deploy tdarr --name my-tdarr
```

See the [service template catalog](/templates-and-registry) for how templates work, and [Getting started](/getting-started) if you have not installed Levelrail yet.
