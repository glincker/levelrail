Connect Bitbucket Cloud once, then point apps at repositories for push deploys, release deploys and per pull request previews.

This page covers how to deploy from Bitbucket Cloud pushes and pull requests.

## What you get

- Push, tag or pull request events that deploy an app or build a preview.
- Repository and branch listing plus webhook registration through `use-as-source`.
- Webhook history with replay, and PR comments and commit statuses.

## Set up

1. Prepare the credential. An OAuth consumer you register in Bitbucket Cloud. Paste its key and secret, then authorize.
2. In the dashboard, open **Settings > Bitbucket App** (`/settings/bitbucket-app`).
3. List repositories with the provider command, then connect one to an app with `use-as-source` and push a commit.

From the CLI:

```bash
levelrail-cli bitbucket-app repos
levelrail-cli bitbucket-app use-as-source <workspace> <repo-slug> --app-name my-app
```

## Permissions and scopes

| Needed | Why |
| --- | --- |
| OAuth consumer | Registered in your Bitbucket workspace and authorized through a redirect. |

## Endpoint and format

Webhook URL per app is generated by Levelrail and registered on the repository by `use-as-source`.

## Security notes

- Provider secrets are encrypted with the master key; each app has its own webhook secret.
- Disconnecting removes the connection and its secrets from the control plane only. Revoke the token or app at the provider as well.
- Nothing you enter here is shown again after you save it.

## Limits and caveats

- Bitbucket Cloud only; self-hosted Bitbucket is not covered.
- Repositories are addressed by workspace and repo slug.
- If webhook registration fails, the whole use-as-source request fails with 502.
- The connection needs a master key on the control plane; routes return 501 without one.

## Troubleshooting

**Authorization fails.** Check the consumer key and secret, and that the callback URL on the consumer matches your dashboard.

**use-as-source returns 502.** Bitbucket webhook registration failed. Confirm the authorizing user can administer the repository.

**A repo is missing from the list.** Use the workspace and repo slug from `bitbucket-app repos`; the consumer only sees repositories its user can access.

## FAQ

**Does it support Bitbucket Server or Data Center?**

No. Only Bitbucket Cloud is covered.

**Is the same consumer used for sign-in?**

No. Sign in with Bitbucket is a separate OAuth app under OAuth sign-in.
