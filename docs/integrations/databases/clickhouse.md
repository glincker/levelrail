Create a managed ClickHouse database with SQL based backups and restore into a new database.

This page covers how to run and back up managed ClickHouse databases.

## What you get

- A ClickHouse 24.8 container with generated settings and its own data volume that survives container recreation.
- Connection details and an injectable connection string for apps.
- Backups as SQL dumps (DDL plus rows), with schedules and retention.

## Set up

1. Prepare the credential. Credentials are generated by Levelrail and exposed through the connection string.
2. In the dashboard, open **Databases > Create database (engine ClickHouse)**.
3. Check the database status on its Overview tab, then take a first backup against a connected target.

From the CLI:

```bash
levelrail-cli databases create --name main --engine clickhouse --version 24.8
levelrail-cli backups schedule set main --target <target-id> --cron "0 3 * * *" --retain 7
```

## Permissions and scopes

| Needed | Why |
| --- | --- |
| Create and manage | A user with write access to databases; public access and deletion are separate decisions in the UI. |

## Endpoint and format

Engine id `clickhouse`. Default version `24.8`. TLS: off.

## Security notes

- Credentials are generated by the control plane and stored with the same envelope encryption as app secrets.
- Deleting a database keeps its data volume and its backups unless you explicitly ask for the data to go.
- Nothing you enter here is shown again after you save it.

## Limits and caveats

- Backups are DDL plus rows as SQL. Hyphens and dots in the database name become underscores inside ClickHouse, so web-db is web_db.
- Only minor and patch version changes are accepted; a major change is refused with 409.
- TLS is not enabled by default.

## Troubleshooting

**The ClickHouse database name differs from mine.** Levelrail sanitizes hyphens and dots to underscores because the image entrypoint puts the name into unquoted SQL.

**Restoring an old backup into a different name fails.** Backups taken before the DDL fix restore only into a database with the same ClickHouse identifier. Newer backups restore as new anywhere.

**set-version returns 409.** Only minor and patch changes are accepted. Back up and restore as new.

## FAQ

**How are ClickHouse backups stored?**

As SQL: DDL followed by rows, uploaded to your backup target.

**Does it have a password?**

Yes, a generated one, unlike the Redis family.
