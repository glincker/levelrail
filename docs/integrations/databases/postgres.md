Create a managed PostgreSQL database with scheduled backups to S3 compatible storage, point-in-time restore and a guarded major upgrade.

This page covers how to run and back up managed PostgreSQL databases.

## What you get

- A PostgreSQL 16 container with generated settings and its own data volume that survives container recreation.
- Connection details and an injectable connection string for apps.
- Backups as pg_dump backups, with schedules and retention.
- Point-in-time restore through WAL archiving, for Postgres only.
- pgvector images through a version such as 17-pgvector.

## Set up

1. Prepare the credential. Credentials are generated by Levelrail and exposed through the connection string.
2. In the dashboard, open **Databases > Create database (engine PostgreSQL)**.
3. Check the database status on its Overview tab, then take a first backup against a connected target.

From the CLI:

```bash
levelrail-cli databases create --name main --engine postgres --version 16
levelrail-cli backups schedule set main --target <target-id> --cron "0 3 * * *" --retain 7
```

## Permissions and scopes

| Needed | Why |
| --- | --- |
| Create and manage | A user with write access to databases; public access and deletion are separate decisions in the UI. |

## Endpoint and format

Engine id `postgres`. Default version `16`. TLS: on by default.

## Security notes

- Credentials are generated by the control plane and stored with the same envelope encryption as app secrets.
- Deleting a database keeps its data volume and its backups unless you explicitly ask for the data to go.
- Nothing you enter here is shown again after you save it.

## Limits and caveats

- Point-in-time restore and the guarded major upgrade are Postgres only.
- A plain Postgres and a pgvector image cannot be swapped with set-version; use major-upgrade, and pgvector back to plain is refused.

## Troubleshooting

**set-version is refused with 409.** A major version change would corrupt the data directory. Use `databases major-upgrade` for Postgres, which dumps and restores.

**Point-in-time restore is not available.** Run `pitr enable <database>` first, and take a base backup. WAL archiving only applies going forward.

**The database is stuck not running.** Check its status condition. The reconciler refuses to start when credentials do not exist yet and reports that as a condition.

## FAQ

**Can I run pgvector?**

Yes. Use a version written `<major>-pgvector` with Postgres 13 or newer, such as 17-pgvector.

**Which backups can verify themselves?**

Scheduled backups that succeed are re-verified automatically; manual ones you verify yourself.
