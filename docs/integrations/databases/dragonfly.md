Create a managed Dragonfly database, a Redis compatible in memory store, with RDB based backups.

This page covers how to run and back up managed Dragonfly databases.

## What you get

- A Dragonfly v1.27.1 container with generated settings and its own data volume that survives container recreation.
- Connection details and an injectable connection string for apps.
- Backups as a dump taken through a backup target, with schedules and retention.

## Set up

1. Prepare the credential. No password by default. Do not publish the port without understanding that anyone who can reach it has full access.
2. In the dashboard, open **Databases > Create database (engine Dragonfly)**.
3. Check the database status on its Overview tab, then take a first backup against a connected target.

From the CLI:

```bash
levelrail-cli databases create --name main --engine dragonfly --version v1.27.1
levelrail-cli backups schedule set main --target <target-id> --cron "0 3 * * *" --retain 7
```

## Permissions and scopes

| Needed | Why |
| --- | --- |
| Create and manage | A user with write access to databases; public access and deletion are separate decisions in the UI. |

## Endpoint and format

Engine id `dragonfly`. Default version `v1.27.1`. TLS: off.

## Security notes

- Credentials are generated by the control plane and stored with the same envelope encryption as app secrets.
- Deleting a database keeps its data volume and its backups unless you explicitly ask for the data to go.
- Nothing you enter here is shown again after you save it.

## Limits and caveats

- Dragonfly starts one io thread per CPU and refuses to start when threads times 256MiB exceed available memory. Set APP_DRAGONFLY_PROACTOR_THREADS on the control plane to cap it.
- Runs passwordless by default.
- A newer major version is allowed, but never going back.

## Troubleshooting

**The container restarts in a loop on a many core host.** Threads times 256MiB exceeds memory. Set APP_DRAGONFLY_PROACTOR_THREADS (for example 2), then remove the container so the reconciler recreates it; the data volume is kept.

**The thread cap has no effect on an existing database.** An existing container keeps the command it was created with. Remove it so it is recreated.

**Attaching username or database is rejected.** Dragonfly does not support those fields. Attach url, host or port.

## FAQ

**Is Dragonfly a Redis drop in?**

It speaks the Redis protocol and Levelrail treats it like the Redis family for backups and connection fields.

**What is the default version?**

v1.27.1.
