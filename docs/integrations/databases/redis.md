Create a managed Redis database with RDB based backups and a connection string you can inject into apps.

This page covers how to run and back up managed Redis databases.

## What you get

- A Redis 7 container with generated settings and its own data volume that survives container recreation.
- Connection details and an injectable connection string for apps.
- Backups as a dump taken through a backup target, with schedules and retention.
- TLS on by default.

## Set up

1. Prepare the credential. No password by default. Do not publish the port without understanding that anyone who can reach it has full access.
2. In the dashboard, open **Databases > Create database (engine Redis)**.
3. Check the database status on its Overview tab, then take a first backup against a connected target.

From the CLI:

```bash
levelrail-cli databases create --name main --engine redis --version 7
levelrail-cli backups schedule set main --target <target-id> --cron "0 3 * * *" --retain 7
```

## Permissions and scopes

| Needed | Why |
| --- | --- |
| Create and manage | A user with write access to databases; public access and deletion are separate decisions in the UI. |

## Endpoint and format

Engine id `redis`. Default version `7`. TLS: on by default.

## Security notes

- Credentials are generated by the control plane and stored with the same envelope encryption as app secrets.
- Deleting a database keeps its data volume and its backups unless you explicitly ask for the data to go.
- Nothing you enter here is shown again after you save it.

## Limits and caveats

- Runs without a password by default; publishing the port gives unauthenticated read and write access, so the dashboard asks you to confirm.
- The username and database fields do not apply to Redis connection strings.
- A newer major version is allowed, but never going back.

## Troubleshooting

**Attaching username or database to an app is rejected.** Redis, KeyDB and Dragonfly do not support those fields. Attach url, host or port.

**Public access toggle asks for confirmation.** The database has no password. Tick the acknowledgement only if you intend to expose it, or keep access private.

**Version downgrade refused.** Redis allows a newer major, never going back. Restore a backup into a new database on the older version.

## FAQ

**Does it have a password?**

Not by default. The instance is passwordless and meant to be reached privately by your apps.

**Can I upgrade major versions?**

A newer major is allowed in place. Take a backup first.
