Create a managed MongoDB database with scheduled backups to S3 compatible storage and restore into a new database.

This page covers how to run and back up managed MongoDB databases.

## What you get

- A MongoDB 7 container with generated settings and its own data volume that survives container recreation.
- Connection details and an injectable connection string for apps.
- Backups as a dump taken through a backup target, with schedules and retention.

## Set up

1. Prepare the credential. Credentials are generated by Levelrail and exposed through the connection string.
2. In the dashboard, open **Databases > Create database (engine MongoDB)**.
3. Check the database status on its Overview tab, then take a first backup against a connected target.

From the CLI:

```bash
levelrail-cli databases create --name main --engine mongodb --version 7
levelrail-cli backups schedule set main --target <target-id> --cron "0 3 * * *" --retain 7
```

## Permissions and scopes

| Needed | Why |
| --- | --- |
| Create and manage | A user with write access to databases; public access and deletion are separate decisions in the UI. |

## Endpoint and format

Engine id `mongodb`. Default version `7`. TLS: off.

## Security notes

- Credentials are generated by the control plane and stored with the same envelope encryption as app secrets.
- Deleting a database keeps its data volume and its backups unless you explicitly ask for the data to go.
- Nothing you enter here is shown again after you save it.

## Limits and caveats

- Only minor and patch version changes are accepted; a major change is refused with 409.
- TLS is not enabled by default.
- No slow query log: that is Postgres and MySQL only.

## Troubleshooting

**set-version returns 409.** MongoDB accepts only minor and patch changes. Back up and restore as new on the new version.

**An app's connection string has no database field.** Check the field you attach: url, host, port, username, password and database are valid for MongoDB.

**A backup fails with 507.** The control plane data directory is below APP_MIN_BACKUP_DISK_MB free. Free space there.

## FAQ

**How do I move to a new major?**

Back up, then restore as new on the new version; an in place major change is refused.

**Is public access safe?**

It gets a generated password, but exposing a database port is still a deliberate choice you confirm in the UI.
