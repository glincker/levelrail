Create a managed KeyDB database, a Redis compatible multithreaded engine, with RDB based backups.

This page covers how to run and back up managed KeyDB databases.

## What you get

- A KeyDB latest container with generated settings and its own data volume that survives container recreation.
- Connection details and an injectable connection string for apps.
- Backups as a dump taken through a backup target, with schedules and retention.

## Set up

1. Prepare the credential. No password by default. Do not publish the port without understanding that anyone who can reach it has full access.
2. In the dashboard, open **Databases > Create database (engine KeyDB)**.
3. Check the database status on its Overview tab, then take a first backup against a connected target.

From the CLI:

```bash
levelrail-cli databases create --name main --engine keydb --version latest
levelrail-cli backups schedule set main --target <target-id> --cron "0 3 * * *" --retain 7
```

## Permissions and scopes

| Needed | Why |
| --- | --- |
| Create and manage | A user with write access to databases; public access and deletion are separate decisions in the UI. |

## Endpoint and format

Engine id `keydb`. Default version `latest`. TLS: off.

## Security notes

- Credentials are generated by the control plane and stored with the same envelope encryption as app secrets.
- Deleting a database keeps its data volume and its backups unless you explicitly ask for the data to go.
- Nothing you enter here is shown again after you save it.

## Limits and caveats

- Runs passwordless by default, and the dashboard asks you to confirm before publishing the port.
- The default version is the latest tag, so pin a version for reproducibility.
- A newer major version is allowed, but never going back.

## Troubleshooting

**Attaching username or database to an app is rejected.** KeyDB does not support those fields. Attach url, host or port.

**Version changes unexpectedly.** The default version is the latest tag. Set an explicit version when you create the database.

**Downgrade refused.** A newer major is allowed but never going back. Restore a backup into a new database.

## FAQ

**Are backups the same as Redis?**

Yes, they are RDB snapshots, checked for the RDB header.

**Does it have TLS by default?**

No. TLS is on by default for Postgres and Redis only.
