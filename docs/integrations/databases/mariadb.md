Create a managed MariaDB database with scheduled backups to S3 compatible storage and restore into a new database.

This page covers how to run and back up managed MariaDB databases.

## What you get

- A MariaDB 11 container with generated settings and its own data volume that survives container recreation.
- Connection details and an injectable connection string for apps.
- Backups as mariadb-dump backups, with schedules and retention.
- Backups are structurally checked for the mariadb-dump completion trailer.

## Set up

1. Prepare the credential. Credentials are generated by Levelrail and exposed through the connection string.
2. In the dashboard, open **Databases > Create database (engine MariaDB)**.
3. Check the database status on its Overview tab, then take a first backup against a connected target.

From the CLI:

```bash
levelrail-cli databases create --name main --engine mariadb --version 11
levelrail-cli backups schedule set main --target <target-id> --cron "0 3 * * *" --retain 7
```

## Permissions and scopes

| Needed | Why |
| --- | --- |
| Create and manage | A user with write access to databases; public access and deletion are separate decisions in the UI. |

## Endpoint and format

Engine id `mariadb`. Default version `11`. TLS: off.

## Security notes

- Credentials are generated by the control plane and stored with the same envelope encryption as app secrets.
- Deleting a database keeps its data volume and its backups unless you explicitly ask for the data to go.
- Nothing you enter here is shown again after you save it.

## Limits and caveats

- Only minor and patch version changes are accepted; a major change is refused with 409.
- TLS is not enabled by default.
- Slow query logs are available for Postgres and MySQL only, not MariaDB.

## Troubleshooting

**set-version returns 409.** MariaDB accepts only minor and patch changes. Back up and restore as new on the new version.

**A truncated backup fails verification.** Verification looks for the dump's completion trailer. Re-run the backup, and check the target has room and permission to write.

**Slow query log returns an error.** Slow query logs are only implemented for Postgres and MySQL.

## FAQ

**Is MariaDB a drop in for MySQL?**

They are separate engines in Levelrail, with their own default version and backups. Pick the one your app targets.

**Does it get point-in-time restore?**

No. That is Postgres only.
