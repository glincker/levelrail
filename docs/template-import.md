# Imported templates

This page is generated by `go run ./scripts/import-templates`. It lists the templates converted from the upstream service catalog (Apache-2.0, see the attribution in `internal/catalog/manifests/NOTICE`) and the reason every other upstream file was left out. The machine-readable version is `docs/template-import-report.json`.

Of 371 upstream files, 65 are committed as installable templates, 201 convert cleanly but are not committed (they overlap an older hand-written entry or were left for a later batch), and 105 were skipped.

## What the converter does

- Address variables become the install form's domain prompts: the upstream URL form resolves to `https://<domain>` and the host form to the bare host.
- Password, user, hex and base64 variables become generated settings with their lengths. A generated value used in a command or healthcheck is exposed to the shell as an environment variable.
- Variables with a default are inlined; variables without one become settings you can fill in.
- Relative bind mounts of directories become named volumes. Mounts of files or of repository content are refused.
- A TCP-only healthcheck on a web service becomes an HTTP probe, and a web service with no healthcheck gets one.
- Every manifest then goes through the same loader, compose validator and Docker guard rules a real install uses.

| Reason | Templates | Meaning |
| --- | --- | --- |
| `bad_template_id` | 1 | The upstream file name is not a valid template id. |
| `bind_mount_needs_file_content` | 23 | Mounts a repository file or directory the platform cannot ship (config files, init scripts). |
| `host_access` | 5 | Needs privileged mode, host networking or added capabilities, which the Docker guard rules refuse. |
| `host_bind_mount` | 20 | Binds a host path such as the Docker socket, which the Docker guard rules refuse. |
| `missing_metadata` | 1 | The upstream header has no documentation link or slogan. |
| `no_domain_port` | 3 | No web port could be found to put behind a domain. |
| `no_healthcheck` | 1 | No service has a healthcheck and none has a web port to probe. |
| `unknown_domain_key` | 1 | An address variable names a service that does not exist. |
| `unsupported_protocol` | 4 | Publishes a UDP port, which compose apps do not support yet. |
| `unsupported_runtime_key` | 16 | Sets a runtime key with no equivalent here (user, ulimits, shm_size, working_dir, read_only, sysctls). |
| `upstream_ignored` | 28 | The upstream catalog marks the template as ignored. |
| `yaml_parse_error` | 2 | The upstream file does not parse as a compose file. |
